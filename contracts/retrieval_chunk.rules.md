# Retrieval chunk rules beyond the schema (retrieval_chunk.schema.json 1.0.0, ADR-0049)

Per-account grounding: Tilo indexes passages of records a person may read and gives the nearest few to that person's
own Quick asks and intake as untrusted data. The schema checks one chunk, one prompt block or one grounding ref. The
rules below need the stores, the people directory, the shares, the clock, the provider layer or the prompt. `RT-` is
this file's prefix and the ids are stable. "Code" means tilo-api and `packages/memory`, never a model. This replaces
ADR-0030 decision 3's summary index (`memory_index`, never built) with this chunk collection; ADR-0030's owner
pre-filter, Scope re-check, profile pinning and erasure rules carry over unchanged.

| Rule | Rule | Checked by | Source |
| --- | --- | --- | --- |
| RT-01 | **What is indexed.** Only by code, only from records already stored and screened `clean`, in five kinds: a run's final deliverable artifact versions (their text form), uploaded files' extracted text, the confirmed minutes of a meeting (summary, decisions, action items; not the transcript), pins, and memory items (MI-02). Never a mail body or snippet (PRD 13.1), a fetched web page (the result cache's), a transcript, a Quick question, a card, an event, a log, another org's record, a record whose screening is not `clean`, or anything flagged. A source is cut into passages of at most 1200 characters on paragraph or sentence boundaries, at most 200 per source version and 2000 per person (beyond that the oldest sources are not indexed). | memory tests | ADR-0049; PRD 13.1, FR-INT-02, PE-05 |
| RT-02 | **Scope at write.** `owner` is the source record's owner (the world owner for a deliverable or upload, the meeting owner for minutes, the pin's `scope.user` or set-up person for a pin, the note's owner). `team_id` is set only for a team pin (PE-02, its team) and for a deliverable of a world that has a share in force with that team when it is indexed (ADR-0040, PE-31); every other chunk has `team_id` null (schema for uploads, minutes and notes). A meeting's minutes are its owner's alone (PE-05), whatever world or team. | memory tests | ADR-0040, ADR-0044; PE-01, PE-02, PE-05, PE-31 |
| RT-03 | **Readable scope first, then ranking.** The store's search takes the org and the caller as required arguments and refuses a blank, wildcard or other org's caller before any query. Code computes the caller's readable filters from the stores at query time: their own chunks (`owner` equal to the caller), and for each team the caller is a current, accepted member of (ADR-0044 `accepted_at`, at most 10 teams), that team's chunks (`team_id` equal to it). Each filter runs as its own `find_nearest` with the filter, `org_id` and `embed_profile` inside the vector query (a composite vector index per shape), never as a filter after ranking; the results merge by distance. Then every hit is re-checked against its source as the source's own read rule says at that moment (the record exists, is not deleted, the same owner; for a team chunk the share is still in force, the caller still a member, the pin still a team pin of that team), and a hit that fails is dropped without a trace in the answer. No route returns a chunk, its text or its existence to anyone. | memory tests (cross-owner and cross-team cases); security review | ADR-0049, ADR-0030; PE-01 to PE-05, PE-31 to PE-33 |
| RT-04 | **Where passages are used.** At most 5 passages (k 5, nearest first, within `max_distance` from config) go, as `prompt_block` fenced and labelled untrusted data in the user turn (never the system prompt, EFF-04), into exactly the two calls of MI-05: the person's own Quick ask and the Director's brief extraction for their own signed-in intake. Never for anyone else's call, an unauthenticated intake, a meeting room, the meeting bot, Autopilot, a draft to someone else, a tool, an event, a log line or a trace field. With no passages the block renders as nothing and the prompt is byte-identical to before (B-007). A Quick answer carries `grounded_on` (one `grounding_ref` per passage given), so nothing is used silently (PRD 13.1); the Director may cite a passage it used in `brief.sources` (`kind: memory`, `ref`: the chunk id), and code keeps only ids it sent. | api; harness tests | ADR-0049; PRD 13.1, EFF-04, HR-1 |
| RT-05 | **Embeddings.** Only through `packages/providers` (`ModelProvider.embed` with the typed `EmbedRequest` and `EmbedResponse` of ADR-0030 MEM30-a) on the config role `embed`. Dev and CI use the deterministic fake (SHA-256 seeded unit vectors, no network, EFF-01); a live profile is added to `config/models.yaml` only with the owner's model choice and price (PL-01, PL-06). A query compares only chunks of the current `embed_profile` and `dimensions`; changing the profile is a re-index, never a mix. | providers tests; config loader | ADR-0030; PL-01, PL-06, EFF-01 |
| RT-06 | **Cost.** One query embedding per ask, skipped when the caller has no chunk (a per-person count the indexer keeps); indexing embeds new passages only (same `text_sha256` and profile: reused) in batches of at most 64. A deliverable's indexing is metered on its run, everything else on the person's per-user allowance (FR-MTR-04). When the cost does not fit, the ask goes on without grounding and the source is indexed at its next change; retrieval never blocks or fails an ask. | api; metering tests | ADR-0030 decision 6; EFF-03, FR-MTR-04 |
| RT-07 | **Deletion and retention.** A chunk never outlives its source version. Deleting or editing a note replaces or deletes its chunks in the same request (MI-02); deleting a pin, a world, an artifact, a meeting or its minutes, or erasing a person deletes their chunks in the same operation through the store's `delete_for_source`, and a daily sweep deletes any chunk whose source is gone or whose `expires_at` (the source's retention) has passed. A team chunk whose share is revoked or whose pin leaves the team is deleted or re-scoped by the next sweep, and RT-03's re-check refuses it until then. The erasure registry (FR-MEM-09) lists the chunk collection and `verify_erasure` re-reads it. | memory tests; erasure script | FR-MEM-09, PRD 16.5 |
| RT-08 | **Untrusted text.** Code removes control characters except line break and tab, format characters and line or paragraph separators, runs the secret redactor, and only then embeds and stores (FR-MEM-05). Retrieved text is data, never instructions: it reaches only the prompt block of RT-04, never a tool argument, card, recipient, outbox entry, event, log or trace. A passage never authorises anything (HR-7). | api; memory tests | FR-MEM-05, SEC-04, HR-7 |
| RT-09 | **Events.** No event type is added. A query writes no event (`memory.hit` stays a verified reuse that saved credits, FR-MEM-02). Indexing a run's deliverables writes ADR-0030's `memory.saved` (`layer: artifact_memory`, `item_count`: the passages indexed) once at run end in that world; other indexing writes no event of its own. | api | PRD 9.5, ADR-0030 |
| RT-10 | **Infrastructure and switch.** Two composite vector indexes on the `chunks` collection group (`org_id`, `owner`, `embed_profile` + `embedding`; `org_id`, `team_id`, `embed_profile` + `embedding`), `DOT_PRODUCT`, the configured dimension, in Terraform (`google_firestore_index`); applying them is the owner's step. Retrieval is off unless `TILO_RETRIEVAL=1`; while an index is missing the query fails, is logged by type and the ask goes on without grounding. Indexing may run before the index exists. | infra; api | ADR-0049; PRD 6.6 |

## Fixtures

- `fixtures/retrieval_chunk/` exercises the stored chunk, `fixtures/retrieval_chunk.prompt_block/` the prompt block and
  `fixtures/retrieval_chunk.grounding_ref/` what an answer shows. Invalid file names say the rule they break.
- RT-01 to RT-10 need the stores, shares, directory or provider layer; they are the memory, api and infra tests'
  (tickets R1a, R1b and R2 in ADR-0049). R1b adds the cross-owner and cross-team leakage cases (two owners with identical
  texts and vectors, a revoked share, a removed member, a pin moved to personal).
