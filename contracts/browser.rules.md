# Agentic browser rules beyond the schema (browser.schema.json 1.0.0, ADR-0051)

ADR-0051 is **Accepted** (owner, 16 Oct 2026). A model looks at one masked screenshot of an isolated tilo-browser
session and proposes one action; code in tilo-api decides; tilo-browser runs only what code allowed and checks again.
The schema checks one body or event. The rules below need the session, the page, the config, the policy engine or
other events. `BR-` is this file's prefix and the ids are stable. "Code" means tilo-api or tilo-browser, never a model.

| Rule | Rule | Checked by | Source |
| --- | --- | --- | --- |
| BR-01 | **The model proposes, code decides.** The `computer_use` role (config/models.yaml, `packages/providers` only) gets the goal, the inputs and page text as delimited data plus at most `model_frames` frames, and must answer one `$defs/action`. Anything else (prose, two actions, unknown keys, coordinates outside 0 to 999) is refused as `invalid_action` and counts as a step. A model never decides authorisation, a host, a cap or a tool. | api loop | PRD 16.3, PL-01 |
| BR-02 | **Egress.** A session browses only `allow_hosts`, built by code when it opens: the hosts typed in the run's request (FR-CON-07 `typed_hosts`) and a used taught skill's `hosts` (TS-18), each also as `*.<host>`; and, for a unit without WT-04 private taint only, the hosts of this run's recorded `web_search` results (at most 10, BQ-SMB-2). Nothing a page or a model writes adds a host. Code refuses a `navigate` outside them as `offsite_host`; tilo-browser's `EgressPolicy` blocks and logs every request the page makes to any other host, subresources included, and counts them in `blocked` (PRD 12.3, 16.2: no data in query strings to other hosts). | api loop; browser | FR-CON-07, SEC-09 |
| BR-03 | **Act on what was inspected.** Before a `click` or `type`, code calls inspect at that point and decides on the returned facts; the act names the inspect's `digest`, and tilo-browser re-reads the element and refuses `target_changed` when the page URL or facts differ. | api loop; browser | 16.3 |
| BR-04 | **No secrets typed.** A `type` into a node with `secure` true is refused (`secure_field`; tilo-browser's `CredentialEntryRefused` holds as well). Text the secret redactor would change is refused (`secret_text`). Tilo never types a password, a one-time code or a card number (PRD 16.1 1). | api loop; browser | 16.1, FR-CON-08 |
| BR-05 | **Commits.** A step is a commit when code finds, from the facts and the action: a click or Enter on a submit control of a `post` form, a `type` with `submit` true in a `post` form, or an element whose name matches the closed commit words in `tilo_browser.commit` (buy, pay, order, checkout, purchase, send, post, publish, submit, delete, remove, confirm, book, reserve, subscribe, sign up, transfer, donate, share, upload), or the provider marks the step as needing confirmation. In a unit with WT-04 private taint (it read workspace data, or a tagged file or Drive item is among its inputs), every `type` is a commit too, so private data never goes into a page without a person. The model's hint can only add a commit, never remove one. Until ticket B3 ships, a commit is refused (`commit`) and the session stops with `needs_person`. With B3, a commit is action `browser_commit` (config/autonomy.yaml T3, always a person): approval.requested with the before-frame as the gate's pinned item, approval.resolved by the person, an outbox entry (connector `web`, destination the session id, item the frame), then the dispatcher's act with `outbox_id`, a `data.transfer` out with the gate's authz, and `browser.acted` verdict `committed`. tilo-browser refuses a commit-like target without an `outbox_id`. | api loop; browser; policy engine; outbox | 10.4, FR-AGT-11, SEC-03, HR-7 |
| BR-06 | **No files in or out.** Downloads are off in the browser context and a click on a `download` element or link to a file is refused (`download`); there is no upload action. | browser; api loop | FR-CON-07, 16.2 |
| BR-07 | **Login walls.** When tilo-browser's `detect_login` fires, the step is refused (`login_wall`), the session stops with `login_wall` and the FR-CON-08 needs-you card is raised (connect by API, upload an export, or skip). | browser; api loop | FR-CON-08 |
| BR-08 | **Caps.** Steps per session at most `max_steps`; credits per session at most `max_credits_per_session`, reserved before each model call through the existing spend ledger (run and daily caps still apply); sessions open at once per world at most `max_sessions_per_world`. Reaching one stops the session (`cap_steps`, `cap_credits`) or refuses to open one. | api loop | FR-MTR-04, PRD 12.3, 6.6 |
| BR-09 | **Frames.** tilo-browser masks every secure node before the PNG leaves it (`ScreenshotRefused` when it cannot). tilo-api stores each frame as an artifact of origin `browser` (AR-11) and only then writes the `browser.started` or `browser.acted` that names it. The Browser panel shows only frames named by recorded events, in order: no video, no interpolation, no frame before its event (HR-1, HR-3). | browser; api; web | HR-1, 12.3 |
| BR-10 | **Person control.** Only the world's owner pauses, resumes, stops or takes over (`control_request`; others get 404). Each op is a `browser.controlled` written through the world's one writer. Pause takes effect before the next model call; stop and take over close the session within one step and write `browser.stopped` (`stopped`, `taken_over`). Take over returns the last page's origin and path only. The existing world pause (Stop all) also stops every session. | api; web | HR-1, 10.2 |
| BR-11 | **Pages are data.** Page text, titles, element names and the model's `ask` question are untrusted data: delimited for the model, escaped on cards and in the panel, and never able to widen hosts, caps, tools or levels. | api; web | 16.3 |
| BR-12 | **Ephemeral sessions.** One context per session, no cookies or storage kept (PRD 16.1 3); `close_request` or `idle_timeout_s` drops everything. A session lost to an instance restart is recorded as `session_lost`, never resumed silently. | browser; api loop | 16.1, FR-AGT-10 |
| BR-13 | **Events carry no content.** `browser.*` events hold the session, host, counts and verdicts: never a full URL, a query, typed text, page text or the model's words. | schema; api | 16.5, SEC-01 |
| BR-14 | **Who calls whom.** Only tilo-api (and the harness) may call tilo-browser (OIDC caller allowlist, `run.invoker`); tilo-browser has no model, data or secret access (infra/ACCESS.md); the model call is made by tilo-api through `packages/providers`. Dev and CI use the fake engine and recorded or fake provider answers, never a paid call (EFF-01). | infra; api; browser | SEC-12, EFF-01 |
