# Meeting brief rules beyond the schema (meeting_brief.schema.json 1.0.0, meeting.schema.json 1.3.0, ADR-0047)

ADR-0047 is **Accepted** (the owner's approval of 16 Oct 2026, 01:15 IST, relayed by the supervisor). The schemas
check one brief document and one meeting record; the rules below need the meeting store, the artifact store, the
prior meetings, the model reply and the session. tilo-api checks them in the brief routes
(`GET` and `POST /v1/meetings/{meeting_id}/brief`), the brief generator and the owner's meeting edit. `MB-` is
this file's prefix; ids are stable. "validator" means the generator's own tests cover the rule (a schema fixture
cannot compare two documents).

| Rule | Rule | Checked by | Source |
| --- | --- | --- | --- |
| MB-01 | **The owner only.** The signed-in principal (the session, never a request field) is the meeting's `owner`. Anyone else, an unknown or other-org meeting, a malformed id and a deleted meeting get the one 404 `not_found` body of a missing meeting (PE-05): an attendee, a Team Lead, an Approver, an org owner and a policy read and make nothing. The owner check runs before every other answer, so `not_ready` reaches the owner only and is no existence oracle. A demo session's `POST` is 403 `demo_read_only`. | api | PE-05, FR-MTG-10 |
| MB-02 | **GET reads, never makes.** `GET` answers 200 with the document `meeting.brief` pins, read through the artifact store in the meeting's own `Scope` (org, world, owner) and validated against `meeting_brief.schema.json` before it answers; `Cache-Control: no-store`. No `brief`, a missing or unreadable version, a failed validation or a failed MB-09 check: 404 `not_ready`. `GET` never calls a model, never meters and never writes. | api | PE-19, EFF-01 |
| MB-03 | **POST makes one now.** Body `{}` (any field refused). A discarded or deleted meeting is 404 `not_found`. One model call on role `meeting_analyst` with template `prompts/meeting_analyst/meeting_brief.md` (the NFR-25 fallback as configured), metered on the owner's existing per-user allowance like minutes (429 `allowance_capped` when spent, nothing called). The result is stored as a new version of the meeting's brief artifact (`application/json`) in the meeting's world (made by the meeting-world maker when `world_id` is absent), then `meeting.brief` is set to that version by a compare-and-set on the meeting; 200 with the document. A model error or time-out: 503 `try_again`, nothing stored, `brief` unchanged. | api | FR-MTG-03, FR-MTR-04 |
| MB-04 | **The agenda is copied by code.** `agenda_points` has exactly one entry per line of the meeting's `agenda` at generation, in the same order, and each `title` and `minutes` equals that line's. The model never adds, drops, reorders or renames a line. | validator | FR-MTG-03, PE-15 |
| MB-05 | **Every talk point cites a source code offered.** The model writes only `talk_points[].text` and picks `evidence` from the sources code listed in the prompt: an `agenda` index below the agenda's length, or a `prior` item of the prior set (MB-06). A talk point whose text fails `line`, or whose cited source does not exist, is dropped (never repaired by a model); at most five stay per agenda line, in reply order. The reply is untrusted data: it never becomes a recipient, a time, a link, a tool call or an instruction. | validator | FR-AGT-12, PE-15 |
| MB-06 | **The prior set.** The latest meeting of the same org and `owner` with the same non-null `series`, `created_at` before this meeting's, status `minuted`, `minutes_confirmed_by` and `minutes` set. Its items are read from the minutes version its `minutes` pins, in its own `Scope`: `ai<n>` is the action item with that `id`, `d<n>` the decision at index n. A meeting with `series` null, or with no such meeting, has an empty prior set: `carry_over` is empty and no source is `prior`. | validator | FR-MTG-03, PE-05 |
| MB-07 | **Carry-over is copied by code.** One `decision` item per decision of the prior minutes and one `open_action` item per action item whose `work_item_id` is null or names a work item that is not `done` or `dropped`; `text` equals the cited item's text exactly and `from_meeting` is the prior meeting. An item whose text fails `line` (a link, for example) is left out; at most 30, decisions first, each list in minutes order. No model writes or edits `carry_over`. | validator | FR-MTG-03, FR-MTG-06 |
| MB-08 | **Flagged.** The SafetyProvider screens the model's input and its reply. A flag sets `flagged: true` and drops every talk point; the code-copied agenda and carry-over stay, and the panel says the brief was flagged. Nothing in a brief is sent anywhere, so `flagged` changes no tier. | validator; web | PRD 16.2, FR-MTG-04 |
| MB-09 | **Deletion follows the sources.** Discarding or deleting the meeting removes `brief` (schema) and deletes its brief artifact versions with the transcript and minutes (FR-MTG-10). `GET` serves a stored brief only while every meeting it cites (`from_meeting`, `prior` sources) still has minutes (not discarded, deleted or past `delete_minutes_after`); otherwise 404 `not_ready`, and the owner may `POST` again. | api | FR-MTG-10 |
| MB-10 | **The owner's two switches.** `brief_requested` and `auto_report` are written only by the owner's meeting edit (`PATCH /v1/meetings/{meeting_id}`; `MeetingEditIn` gains both as strict booleans, a sent field only, null refused), never by a model, another route, an attendee or a policy; absent means off. `brief_requested` lets the T-15 sweep (after submission) make the brief for the owner; until that sweep exists it has no automatic effect and the panel promises none. `auto_report` lets Wrap-up hand the minutes report to the owner's own digest mail, under a per-meeting key, which sends only under the owner's standing policy for `send_email` to self (T2, L3 by policy only) and otherwise sends nothing. Mail to attendees stays a T3 card (FR-MTG-08); no switch changes a tier or a recipient. | api | FR-MTG-08, FR-CHN-18, PE-15 |
| MB-11 | **Hidden characters.** tilo-api removes or refuses astral format and default-ignorable characters (U+E0000 to U+E0FFF) in talk-point text and copied text before the schema check, as for the meeting title (PE-13). | api | PE-13 |
| MB-12 | **No side effect, no new event.** Making a brief writes no outbox entry, gate, card, policy, message or notification; it writes the brief artifact (`artifact.created` the first time, `artifact.versioned` after, both registered, in the meeting's world) and `meeting.brief` (no event, like `world_id`). Nothing animates without those events (HR-1). | api | HR-1, PRD 9.5 |
