# @ mention rules beyond the schema (mentions.schema.json 1.0.0, ADR-0051)

ADR-0051 is **Accepted** (owner, 16 Oct 2026). Typing @ in the chat composer or the Home prompt box lists what the
person may tag; a message carries typed refs, never content. `MN-` is this file's prefix and the ids are stable.
"Code" means tilo-api, never a model. Not the pinboard @mention of a teammate (`mention.schema.json`, PE-06).

| Rule | Rule | Checked by | Source |
| --- | --- | --- | --- |
| MN-01 | **Refs, not content.** A message sends at most 10 unique refs (the `refs` field of `POST /intake`, a JSON array of `$defs/ref`). Pasted text stays text; a label never travels back (MN-08). | api | FR-PA-11, 16.3 |
| MN-02 | **Resolve again, as the sender.** Before use, code resolves every ref with the signed-in person's own permissions at that moment: own and current-team taught skills (TS-01), library skills outside internal domains, artifacts of worlds the person owns or reads through a team share (ADR-0040), Drive items in the person's picked set (ADR-0048 WT-07), worlds as `GET /worlds` lists them, teammates by the PE-20 projection, connectors and tools from the person's registry view. A ref that fails any check gets exactly the same 422 `ref_error` as one that does not exist, so no answer reveals what exists. | api | FR-PA-11, FR-PA-17, PE-20 |
| MN-03 | **The picker lists only what MN-02 would accept**, from the same reads, filtered by `q` in code (case-insensitive substring of the label, no model), `limit` at most 50, cursor paged, rate limited per person by the existing SEC-10 limiter (`rate_limit.py`, config/rate_limits.yaml), and the web waits 250 ms after the last key before asking. A teammate shows id and display name only. | api | SEC-10, PE-20 |
| MN-04 | **What a tag does.** skill or taught_skill: the run uses that skill at the version current when the run starts (pinned, `skill.loaded`; a taught skill's plan steps are the plan outline, TS-04 re-checks them). file: that artifact version becomes a run input. drive_file: read through `read_file` as the owner (`data.transfer` in). drive_folder: listed through `list_files`, which sees only files picked or made by Tilo in it (state `limited`). world: its delivered results are context. person: the display name only, never their personal items (FR-PA-11), and never a recipient without a gate. connector or tool: preferred by the planner within what is allowed. | api; harness | FR-AGT-03, FR-CON-05, FR-PA-11 |
| MN-05 | **A tag never widens.** Tools used are the role's and the skills' allowlists intersected with the team's levels (FR-ACC-01, -02) and the declared config; a tagged tool outside them is refused with the MN-02 body. Every side effect still goes through the policy engine and the outbox; T3 needs a person. | api; policy engine | FR-ACC-02, SEC-03 |
| MN-06 | **Quick keeps no record.** A Quick message with refs answers `switch_to_thinking` with reason `refs`, as attachments do (BQ-COSTFAST); the web sends a message with refs as a Thinking request. | api; web | ADR-0051 |
| MN-07 | **Shared worlds.** When the message starts or continues a team-shared world, the picker marks personal items, and the chip says the run's results are visible to that team (ADR-0040). Personal items of another person are never listed. | web; api | FR-PA-11, ADR-0040 |
| MN-08 | **Labels are display only.** `option.label` and `detail` are written by code from the record; code never reads a label from a request, and refs carry only kind, id and (for a file) version. | api | 16.3 |
| MN-09 | **Provenance through existing events.** No new event: a tagged skill shows as `skill.loaded`, a file input as the run's input artifact, a Drive read as `data.transfer` in. A ref that resolves to nothing usable stops intake with the 422 before any world is created. | api | HR-1, FR-AGT-03 |
| MN-10 | **No paid call to list.** The picker and the resolver make no model call. | api | EFF-01, FR-PA-19 |
