# Website rules (ADR-0050)

A native website is one self-contained HTML file that a writer unit makes for a deliverable whose format is
`website` and whose `make_with` is `native` (or not set). The contract holds the kinds: `deliverable_format`
`website` and `media_type` `text/html` (common 1.8.0), and the HTML version's origin and size cap (artifact 1.2.0,
AR-10). The schema cannot see the bytes, so every rule below is code: the static checker (WEB-1), tilo-api's
preview shell and download (WEB-2) and the web Result panel (WEB-3). No model decides any of them, and none of them
is ever relaxed for one task. Rule ids are stable.

| Rule | Rule | Checked by | Source |
| --- | --- | --- | --- |
| WS-01 | **One file, by a writer.** Only a `writer` unit of a deliverable whose format is `website` and whose `make_with` is native may output `text/html`, and at most one HTML output per unit. Code sets that media type from the unit's role and deliverable, never from the model's reply. HTML from any other unit fails that unit (FR-AGT-13). An upload, a fetch or a render never stores HTML (schema, AR-10). | harness; store (schema for the origin) | ADR-0018 1 |
| WS-02 | **Size and encoding.** 1 to 524,288 bytes (schema) of valid UTF-8: no byte-order mark, no NUL and no other C0 control but tab, line feed and carriage return. After optional whitespace the file starts with `<!doctype html>` in any letter case. | checker (schema for the size) | |
| WS-03 | **Parsed, then scanned.** The checker tokenises the file with an HTML tokenizer and checks every start tag, attribute, `<style>` text and `<script>` text it yields (WS-04 to WS-07), with character references decoded first (`&#106;avascript:` is `javascript:`). A file it cannot tokenise, or that ends inside a tag, a comment, `<script>` or `<style>`, is refused. WS-08 then scans the raw bytes on its own, so a tokenizer that reads the file differently from a browser still cannot let a URL through. | checker | |
| WS-04 | **Elements.** Refused: `base`, `link`, `iframe`, `frame`, `frameset`, `object`, `embed`, `applet`, `portal`, `fencedframe`, `form`; `meta` other than `<meta charset>` and `<meta name="viewport">` (so no `http-equiv`, no refresh); `script` with a `src` attribute or a `type` other than none or `text/javascript` (no modules, import maps or speculation rules); `a` and `area` with `target`, `download` or `ping`; any `srcdoc` attribute. | checker | |
| WS-05 | **URLs.** Every URL attribute (`href`, `xlink:href`, `src`, `srcset`, `imagesrcset`, `poster`, `background`, `cite`, `data`, `codebase`, `longdesc`, `lowsrc`, `dynsrc`, `icon`, `usemap`, `archive`, `profile`) is empty, a fragment (`#` then letters, digits, `-` or `_`), or a `data:` URL of an image (`png`, `jpeg`, `gif`, `webp`), a font (`woff2`, `woff`, `ttf`, `otf`) or an audio or video type; each `srcset` candidate likewise. `action`, `formaction`, `ping` and `manifest` are refused outright. Every other value is refused: `http:`, `https:`, `ws:`, `blob:`, `file:`, `javascript:`, `vbscript:`, `data:text/html`, a protocol-relative `//` and a relative path alike. | checker | |
| WS-06 | **CSS.** In `<style>` text and `style` attributes, after CSS escapes are decoded: no `@import`; every `url(`, `image-set(` and `src(` argument is a `data:` URL of WS-05's types; no `expression(`, `behavior`, `-moz-binding`. | checker | |
| WS-07 | **Script.** Inline `<script>` text and every `on*` attribute value hold no `://`, no `import` keyword and none of these names as a word, compared case-sensitively as JavaScript does (strings and comments included): `fetch`, `XMLHttpRequest`, `WebSocket`, `WebTransport`, `EventSource`, `sendBeacon`, `RTCPeerConnection`, `Worker`, `SharedWorker`, `serviceWorker`, `importScripts`, `eval`, `Function`, `postMessage`, `opener`, `frameElement`. `constructor` is refused when a `.` or a quote comes right before it (a class's own `constructor()` stays allowed). These globals are refused unless a `.` comes right before them (so `el.style.top` stays allowed): `location`, `navigation`, `history`, `top`, `parent`, `frames`, `open`; and so are `window.`, `self.`, `globalThis.` or `document.` followed by any of them, `document.domain`, `document.cookie`, `document.write`, `document.writeln`, a `[` right after `window`, `self`, `globalThis` or `document`, and a `setTimeout` or `setInterval` whose first argument starts with a quote or a backtick. The point: no network, no navigation, and what the checker reads is what runs. | checker | |
| WS-08 | **Raw scan.** Over the whole file, letter case ignored and independent of WS-03: no `://`, `javascript:`, `vbscript:`, `data:text/html`, `<base`, `http-equiv` or `@import`. A site that mentions an address writes it without the scheme (`example.com/page`). | checker | |
| WS-09 | **Refusal.** The checks run on the exact bytes the store would keep, after the secret redactor (AR-07). A file that fails WS-02 to WS-08 is never stored: the writer's output fails with one reason code (`ws_size`, `ws_encoding`, `ws_element`, `ws_url`, `ws_css`, `ws_script`, `ws_raw`) and the line number, which the retry prompt gets (FR-AGT-13); a reason never quotes the file. After the retries the unit fails and the run says what it could not make (FR-INT-15). The store's put runs the same checker for every `text/html` version (AR-10), so no path stores unchecked HTML. A model never overrides the checker. | checker; store | FR-AGT-13 |
| WS-10 | **Preview origin.** The web app never renders the HTML in its own origin or under its own CSP: no `srcdoc`, `blob:` or `data:` frame and no `innerHTML` of it (all three inherit the app's origin or policy). It frames tilo-api's fixed preview shell (`GET /preview/website`: the same bytes for every caller, no data, no token, no sign-in) as `<iframe sandbox="allow-scripts" referrerpolicy="no-referrer" allow="">`, never with `allow-same-origin`, `allow-forms`, `allow-popups`, `allow-modals`, `allow-top-navigation`, `allow-downloads` or `allow-storage-access-by-user-activation`. The shell's response carries `Content-Security-Policy: sandbox allow-scripts; default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; font-src data:; media-src data:; connect-src 'none'; form-action 'none'; base-uri 'none'; frame-src 'none'; worker-src 'none'; object-src 'none'; manifest-src 'none'; frame-ancestors <the web app's origins>`, plus `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, a `Permissions-Policy` that turns every feature off, and no `X-Frame-Options`. The CSP `sandbox` directive keeps the shell in an opaque origin even when it is opened on its own. The web app's own CSP adds tilo-api's origin to `frame-src` and nothing else. | api; web | 16.2 |
| WS-11 | **Preview handshake.** The web app reads the version's bytes through the owner-scoped result route with the person's bearer token (no token in any URL) and checks their SHA-256 against the version's `content_sha256`. It then waits for the shell's one `{"tilo":"preview-ready"}` message (its `source` is that frame's window, its `origin` `"null"`) and posts `{"tilo":"preview","html":<text>}` once, with target origin `*` because an opaque origin cannot be named. The shell's fixed script takes exactly one message whose `origin` is one of the web app's origins, then runs `document.open()`, `document.write(html)` and `document.close()`; the written page keeps the shell's CSP and sandbox. The shell ignores every later message, and the web app every message after the first ready. | api; web | |
| WS-12 | **Leaving closes it.** CSP cannot stop a frame from navigating itself, so WS-05 and WS-07 refuse navigation and the web app watches the frame: a `load` event after the shell's first one means the page navigated, and the app removes the frame at once and says the preview tried to leave Tilo and was closed. | web | |
| WS-13 | **Download.** The `.html` download comes from the owner-scoped result route with `Content-Type: text/html; charset=utf-8`, `Content-Disposition: attachment; filename="<safe title>.html"`, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store` and WS-10's CSP, so a browser that renders it anyway runs it sandboxed and offline. The web app saves it from a `Blob` typed `application/octet-stream` through an anchor's `download` attribute; it never makes a `text/html` blob URL and never opens the file in a tab. | api; web | |
| WS-14 | **Honesty (HR-1).** The preview and the download show only the stored version that the world's `artifact.delivered` names (format `website`, `make_with` `native`), byte for byte (AR-01 and WS-11's hash check). Nothing is re-rendered, repaired or injected; the panel names the version; a version that fails the hash check is not shown. | api; web | 9.4 HR-1 |
| WS-15 | **Who sees it.** The file reaches the people who may read the world's results (the result route's rule) and nobody else. Publishing or sharing it outside Tilo is T3 (`share_file`, `external_sharing`), as for the AppSpec (ADR-0029 decision 9). | api; policy engine | 10.4 |
