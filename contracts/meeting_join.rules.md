# Meeting join rules beyond the schema (meeting_join.schema.json 1.0.0, ADR-0024 amendment 4)

ADR-0024 amendment 4 is **Accepted** (the user's approval of 8 Oct 2026, relayed by the supervisor). The schema
checks one response body; the rules below need the meeting record, the host receipt, the token broker, Google's
answer, the clock and the browser. The connector (`MeetingHostAdapter.join_link`, ticket JOIN-a) checks MJ-03 and
MJ-04 before it returns; tilo-api (`GET /v1/meetings/{meeting_id}/join`, JOIN-b) checks MJ-01, MJ-02 and MJ-05 to
MJ-09 and the agenda's MJ-10; the web (JOIN-c) checks MJ-07 again before it opens anything. API and web notes:
`services/api/tests/API_MTG09_d_join.md`. `MJ-` is this file's prefix; ids are stable. MH-20 and MH-21 are the
connector's refusal ids already reserved for `join_link` (`services/connectors/tests/API_FR_MTG_09.md`).

| Rule | Rule | Checked by | Source |
| --- | --- | --- | --- |
| MJ-01 | **The owner only.** The signed-in principal (the session, never a request field) is the meeting's `owner`, the owner of the meeting's world (PE-12) and the `owner` of its host receipt. Anyone else, an unknown or other-org meeting, a malformed id and a deleted (tombstoned) meeting get one and the same 404 body as a missing meeting (PE-05): an attendee, a Team Lead, an Approver, an org owner and a policy get nothing. | api | PE-05, PE-12, ADR-0024 d3 |
| MJ-02 | **A meeting Tilo hosts, still standing.** The meeting's `status` is `scheduled`, `joining` or `live`, its `source` is `bot`, and its world holds the host receipt of a sent `create_meeting_event` (found through that world's own records in its Scope: the `artifact.created` caused by the `meeting_host` `data.transfer`, its hash-checked bytes parsed as `meeting_event_receipt` with this `meeting_id`). No receipt, another status, or a receipt of another meeting: 409 `not_joinable`. | api | FR-MTG-09, ADR-0024 d4 |
| MJ-03 | **One narrow read.** One `GET .../calendars/primary/events/{event_ref}` on the host account, with the token of `(owner, "meeting_host")` and scope `calendar.events.owned` only, `params == {"fields": "status,hangoutLink"}` exactly, not patient (no waiting retry). Google's `status` `cancelled`, a 404 or 410 refuse with MH-20 (409 `not_joinable`). Every other key of Google's answer is ignored and never copied. It is a read on Tilo's own event, not a side effect: no outbox entry, no gate, no policy. | connectors | ADR-0024 d2, PPL-60c |
| MJ-04 | **Only a Meet link passes.** `hangoutLink` fullmatches `https://meet\.google\.com/[a-z]{3}-[a-z]{4}-[a-z]{3}` (MH-21), else 409 `no_join_link` (also when Google has no link yet, `conference` `pending` or `failure`). tilo-api validates the whole body against `meeting_join.schema.json` before it answers and refuses (409 `no_join_link`) on any error. A refused value is never echoed, logged or put in an exception message: the rule id only. | connectors; api | FR-MTG-01 |
| MJ-05 | **Stored nowhere.** The link lives only in the request's local variables and the response body. No store, cache (the result cache and decision store included), event, card, notification, digest, assistant answer, archive record, artifact, manifest, metric label, trace span, log line at any level, exception text or error report holds it; `meeting.schema.json` and `calendar_entry.schema.json` keep no field that could. The answer is `Cache-Control: no-store` (the `/v1/` middleware). | api; connectors | FR-MTG-01, PE-13 |
| MJ-06 | **Short-lived.** `expires_at` is the server clock (`deps.get_clock`) plus 60 seconds. The web drops the link at `expires_at` or when the view that asked closes, whichever is first, and a later click asks again. | api; web | ADR-0024 am. 4 |
| MJ-07 | **The browser opens only a Meet link.** Before opening, the web checks the same fullmatch and that `new URL(join_url)` has origin `https://meet.google.com`, no user info, no search and no hash; a link that fails is not opened and the page shows a fixed message without it. It opens in a new tab with `rel="noopener noreferrer"` (an anchor) or `window.open(url, "_blank", "noopener,noreferrer")`, and never puts the link in the address bar, history state, `localStorage`, `sessionStorage`, IndexedDB, a service-worker cache, the console, analytics or an error report. | web | SEC-10, PRD 16 |
| MJ-08 | **Bounded.** At most 10 join requests a minute per principal, counted before Google is asked (429 with `Retry-After`). `NotConnected`, `ConnectionExpired` or `InsufficientScope` on the host grant: 409 `host_not_connected`; Google 429, 5xx, a timeout or a lost answer: 503 `try_again`. No retry that waits inside the request. | api | SEC-10, BQ-JOIN-3 |
| MJ-09 | **No event, no run.** A join writes no event (it changes no world, so nothing animates, HR-1), starts no run, no bot and no model call, and is metered at zero (the Calendar API is not billed). The access log line names the route, status and principal only. | api | HR-1, EFF-01 |
| MJ-10 | **The calendar offers Join only where it works.** An `agenda_item` row has `joinable: true` only for a `meeting` row whose meeting passes MJ-01 and MJ-02 for the reader at read time (schema: `joinable` true forces `kind` and `source.kind` `meeting`). The row never carries the link; a synced Google copy of the same event (`source` `google`) is never joinable. | api | FR-CAL-01, PE-13 |
