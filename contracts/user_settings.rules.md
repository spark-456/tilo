# User settings rules beyond the schema (user_settings.schema.json 1.0.0, ADR-0039)

ADR-0039 was accepted by the user on 12 Oct 2026. The schema checks one document or one write body. The rules
below also need the principal, the stored version, the zone database or the clock. `USET-` is this file's prefix
and the ids are stable. "Code" means tilo-api or the channels filter, never a model.

| Rule | Rule | Checked by | Source |
| --- | --- | --- | --- |
| USET-01 | **Whose.** `GET` and `PUT /v1/me/settings` are the only routes. Owner and org come from the verified Principal, never from a path, query or body: the schema refuses an `owner_id`, `org_id` or `updated_at` in an `update`. Every signed-in user owns their own document whatever their org role. No teammate, org owner, Approver or Team Lead reads or writes another person's, and no route lists them. A request without a verified Principal answers 401 and touches nothing. The document lives only in the settings store keyed by org and user: not in a person record, a context or team list, or a browser write to Firestore. | api | FR-SET-01, FR-SET-02, PE-20 |
| USET-02 | **Writes are whole and checked.** A `PUT` carries the whole `update` and is applied atomically: all of it or none. `version` must equal the stored version (0 when nothing is stored), and a stale one answers 409 with nothing written. A body that the schema or USET-03 refuses answers 422 with nothing written, and the stored document stays as it was. A good write stores `version` + 1, `updated_at` from the server clock, and `owner_id` and `org_id` from the Principal, and answers with the stored document. A `GET` with nothing stored answers the unsaved defaults with `version` 0, and a client shows a save as done only after the server's answer. The defaults are code or config, not this contract. Fixture cases: `fixtures/user_settings/crossref/`. | api | FR-SET-01 |
| USET-03 | **Values the schema cannot compare.** `working_hours.start` is before `working_hours.end`. `quiet_hours.start` is not `quiet_hours.end` (an equal pair would read as never quiet; a window that crosses midnight is fine). `profile.time_zone` and `quiet_hours.timezone` are names the zone database (`zoneinfo` with tzdata) knows. `threshold.currency` is an ISO 4217 code that tilo-api has a minor unit for. Each failure is refused with the field named, never corrected quietly. Fixture cases: `fixtures/user_settings/crossref/`; the currency check is the api's alone. | api | FR-SET-01, FR-SET-02, FR-HIL-13 |
| USET-04 | **Decisions keep a channel.** The `decisions` row is never all off (schema). Any other row may be all off. The server refuses an all-off decisions row even when a client skipped its own guard. | schema; api | FR-SET-02, FR-HIL-13 |
| USET-05 | **Quiet hours never hide a gate.** The stored `quiet_hours` object has no field that selects, delays or drops a gate. While its window is active, delivery follows `tilo_channels.quiet_hours.should_notify` (only `gate` and `blocked` notify, FR-HIL-13) and every card and Needs you row stays visible in the app. `threshold` is typed money or null, and no delivery code reads it in this release: a gate carries no structured amount to compare it with, and it may never be used to withhold a gate, a card or a Needs you row. Using it to narrow a push needs its own ADR and a typed amount on the gate. A string such as "£1,000" is refused, never parsed. | schema (shape); channels tests | FR-SET-02, FR-HIL-13 |
| USET-06 | **Profile is display data.** The email is never a sign-in identity, a verified destination, a recipient, a directory record or a connector grant, and name, title, language and working hours change none of those either. A recipient is resolved server side from the directory (PE-09). `time_zone` here is this person's own preference; neither it nor `person.time_zone` overwrites the other. | api | FR-SET-01, PE-09, PE-20 |
| USET-07 | **Preferences authorise nothing.** A settings read or write sends nothing, binds no address, grants no consent, changes no outbox policy or autonomy level and starts no work. No gate, `authz` or policy reads a preference as an approval (PRD 10.4, HR-7). Saving a channel choice does not verify the channel or prove a delivery. | api | FR-SET-02, HR-7 |
| USET-08 | **No event, no content in events or logs.** No event type is added and a settings write writes no world event. Profile text, email addresses and notification choices never enter a world event, a log line, the raw archive or a trace. If an audit event is wanted later, it is a separate contract of ids and counts. The document is kept until the person is erased (FR-MEM-09), which deletes it. | api | FR-SET-01, HR-1, FR-MEM-09 |

## Fixtures

- `fixtures/user_settings/{valid,invalid}/` exercise the stored document and `fixtures/user_settings.update/`
  the write body. Invalid file names say the rule they break.
- `fixtures/user_settings/crossref/{valid,invalid}/` (contracts-check skips this folder): each file is
  `{rule, note, stored_version, update}`; `update` is shape-valid, and an invalid file breaks only the rule in
  its `rule` field (USET-02, USET-03). The oracle is in
  `tests/contracts/test_FR_SET_01_02_user_settings_contract.py`, and the api tests run the same files.
