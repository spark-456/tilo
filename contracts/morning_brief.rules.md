# Morning brief rules beyond the schema (morning_brief.schema.json 1.0.0, ADR-0049)

The schema checks one brief, one settings answer or one settings body. The rules below also need the principal, the
clock, the person's grants, the read results, the plate, the model's reply or the digest path. `MO-` is this file's
prefix and the ids are stable. "Code" means tilo-api, never a model. The calendar and mail reads are ADR-0048's
`read_events` and `search_email` (`POST /internal/workspace/read` on tilo-connectors); this file does not define them.

| Rule | Rule | Checked by | Source |
| --- | --- | --- | --- |
| MO-01 | **Whose.** `GET` and `PUT /v1/me/brief-settings`, `GET /v1/me/brief` (today's latest version, or 404 `not_ready`) and `POST /v1/me/brief` (body `{}`, make one now) are the only routes. Owner and org come from the verified Principal, never from a path, query or body; no route takes a user id or a date, and no teammate, org owner, Approver or Team Lead reads another person's brief or setting. A brief is stored only in the person's own Desk world (PE-12), never a shared world; its events carry `vis: []`. A demo session never reads a Google account: it gets `not_connected` sections and an in-memory store. A request without a verified Principal answers 401. | api | ADR-0049; PE-12 |
| MO-02 | **The setting.** Off by default. With nothing stored, `GET` answers `enabled` false, `time` 07:30, `time_zone` the person's saved settings zone (USET) else UTC, `email_copy` false and `updated_at` null. `PUT` takes the whole `settings_update`, refuses a zone the zone database does not know (422, field named), stores it with `updated_at` from the server clock and answers `settings`. `email_rule_ready` is computed at each answer (MO-10). A setting sends nothing, grants no consent, connects no account and changes no policy or tier (as USET-07). | api | ADR-0049; USET-03, USET-07 |
| MO-03 | **Schedule.** The Scheduler's tick (`POST /internal/schedules/tick`, Scheduler mode) runs a brief sweep, off unless `TILO_MORNING_BRIEF=1`. For each person with `enabled` true whose local time is at or after `time` and less than 3 hours after it, and who has no `schedule` version for that local date, code first claims `(org, user, local_date)` atomically (one claim, so two ticks or instances make one brief), then makes a brief with `trigger: schedule`. At most 10 briefs per tick; the rest wait for the next tick. A person whose window has passed gets none that day. Whatever fails is logged by type only and never changes the tick's answer. | api | ADR-0049; FR-AGT-14b pattern |
| MO-04 | **On demand.** `POST /v1/me/brief` makes a version now (`trigger: on_demand`) whatever `enabled` says, at most 3 times per person per local date (429 `brief_limit`, nothing read). A version adds to the day's artifact; `GET` answers the latest. | api | ADR-0049 |
| MO-05 | **What is read.** Only the person's own: `read_events` on their own primary calendar for `local_date` in `time_zone` (meetings, at most 20 by start); `search_email` on their own mailbox for messages received in the last 24 hours in the inbox, excluding promotions, social, spam and trash, `max_results` 10 (mail); and the person's own plate (PE-27) rows with a `due` on or before `local_date` plus 2 days whose record is a work item, pin or world (deadlines, at most 20 by due date). No message body, snippet, attachment, guest list, location or link is read into a brief, and nothing from a teammate's record (PE-33) or another person's account. The reads use the person's own grants, are made with `user_id` the person and never from a demo session, and are recorded as ADR-0048 records a read, in the person's Desk world. A read that answers `not_connected` or `missing_scope` makes its section `not_connected`; any other failure `unavailable`. | api | ADR-0049, ADR-0048; PE-27, PE-33 |
| MO-06 | **Copied by code, cleaned.** Code copies every meeting, mail and deadline field: the meeting's title, times, all-day flag and attendee count; the sender's display name (never the address), the subject and the receipt time; the plate row's title and due date. Each text is cleaned like a quote (PE-24: addresses, phone numbers and links replaced by `[removed]`; Cc, Cf, Zl and Zp removed, astral ones included; cut at the field's cap on a word boundary) and passes the secret redactor. A meeting title empty after cleaning becomes "Untitled event"; a sender name or subject empty after cleaning is null. The subjects and sender names of one brief are screened once by the safety provider; a flagged message is left out of the brief. | api | ADR-0049; PE-24, SEC-01, SEC-04 |
| MO-07 | **The one model call.** At most one JSON-mode call per brief, on the existing role `assistant` (no config change), made only when there is at least one meeting, mail or deadline. Its prompt is a static system template and a user turn that lists the copied items as numbered, fenced, untrusted data (never instructions). Its reply may hold only `needs_reply` (message numbers, at most 10), `suggestions` (at most 5: text and 1 to 5 item numbers) and `todos` (at most 5: title, due words, one message number). Code keeps only numbers it offered, checks each text against the schema and MO-06's cleaning, and drops an entry that fails (never repairs it). The reply is screened; a flagged reply drops every model part (`model: flagged`). The call is metered on the person's per-user allowance (FR-MTR-04); one that does not fit, errors or times out leaves `model` skipped or failed. The model never writes a meeting, mail or deadline field, a status or a source. | api | ADR-0049; EFF-03, FR-MTR-04, SEC-04 |
| MO-08 | **Citations.** Every `suggestions[].cites` entry equals the `source` of an item in this brief's `meetings`, `mail_needing_reply` or `deadlines`; every `todo_suggestions[].mail` is a message that this brief's mail search returned, copied as MO-06 copies mail. A brief that breaks this is not stored. | validator | ADR-0049; HR-1 |
| MO-09 | **Storage and events.** A brief is one version of the artifact `art_mbrief_<yyyymmdd>` (local date) in the person's Desk world, `application/json`, origin and screening as the meeting brief's (ADR-0047). The first version writes `artifact.created`, each later one `artifact.versioned`, actor the person (on demand) or `system` (schedule), `vis: []`, `district` null, and a summary that names no title, subject, sender or count of mail (for example "Tilo made your morning brief."). `GET` answers the latest version for today's local date in the setting's zone and checks its `owner` equals the principal. The sweep deletes brief artifacts older than 7 local days, and the erasure registry (FR-MEM-09) covers briefs, settings and claims. | api | ADR-0049, ADR-0047, ADR-0018; PE-12, FR-MEM-09 |
| MO-10 | **Email copy.** Only for a `schedule` brief with `email_copy` true, and only through the owner-only digest path: `DigestService.enqueue_text(kind="morning_brief")` to the person's own directory address under their own standing L3 `send_email` rule pinned to that address with no undo window (the plate mailer's check, `email_rule_ready`), after the quiet-hours check (`should_notify("digest")`). The body is plain text code renders from the stored version: the three sections and the suggestions, no link, no address. At most one per person per UTC day (the digest key); a second version the same day sends nothing more. A failed or skipped send leaves the in-app brief as it is. | api; channels | ADR-0049; FR-CHN-18, FR-PA-06, PE-09 |
| MO-11 | **A brief acts on nothing.** Making, reading or emailing a brief writes no outbox entry but MO-10's, and no gate, card, policy, Decision, consent or message. A suggestion is text that may open the item it cites in the app. A to-do becomes a work item only when the person confirms it, through the existing `POST /v1/work-items` with `source: {kind: mail, ref: <message id>}`; PE-08's "a mail source must belong to P" holds for a message id that appears in the person's own stored brief of the last 7 days (the source-owners seam vouches for it). The work item is the person's own (`created_by` person), and its due date is computed by code from `due_text` (PE-15). | api | ADR-0049; PE-08, PE-15, HR-7 |
| MO-12 | **Honest states.** Each section's `status` says whether it was read; the web shows `not_connected` as "connect your calendar/mail", `unavailable` as "could not read it today" and `unsorted` as "unread mail" (never as "needs a reply"), and never shows an empty unread list as "nothing needs you". It shows `generated_at`, and a `GET` before the first brief of the day as "your brief arrives at <time>". No text says a mail was answered, a meeting confirmed or a to-do added until that write has committed. | web | ADR-0049; HR-1 |

## Fixtures

- `fixtures/morning_brief/` exercises the stored brief, `fixtures/morning_brief.settings/` the settings answer and
  `fixtures/morning_brief.settings_update/` the PUT body. Invalid file names say the rule they break.
- MO-01 to MO-12 compare against the principal, the clock, reads, the plate, the reply or the digest path; they are
  the api tests' (tickets B1a and B1b in ADR-0049), not fixtures. MO-08's check is the generator's own test.
