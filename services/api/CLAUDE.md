# services/api — `tilo-api`

## Purpose
Cloud Run service (PRD 6.2): sessions, tasks, cards, approvals, policies, downloads, sharing, RBAC. The only service the web client and channels write through; the client reads live state from Firestore under rules.

## Commands
- `uv run --package tilo-api pytest` — tests; `just check` — gate; `just dev-api` — dev mode on 127.0.0.1:8080 (fake Director); `Dockerfile` runs `tilo_api:app`, deploy `docs/deploy-dev.md`

## Contracts and config
- Reads/writes `packages/contracts-py` types; Firestore (worlds, events, cards, policies, grants; deployed via `store_door` -> `durable_store.DurableStore`, a write-through cache, `Store.save`: ADR-0026, BQ-PW-1; dev keeps the plain `Store`); Cloud Tasks. Config:
  `autonomy.yaml`, `flags/`, `connectors.yaml` (RBAC and routing only), `teams.yaml`, `scenarios/`, `out_of_policy.yaml`, `capability_gaps.yaml`.
- Env: `TILO_API_DEV=1`; `TILO_API_DEV_ORIGINS` (default `http://localhost:5173`); `TILO_DEV_UNIT_DELAY_S` (1.5, 0..10); `TILO_JUDGE_LIVE=1`; `TILO_API_CORS_ORIGINS` (WEB-TO-API, `tilo_api.cors`: exact https origins, any bad entry = no CORS, outermost, no credentials); `TILO_APPCHECK_ENFORCE` (SEC-10, `tilo_api.appcheck`, BQ-SEC10-1..3: only exactly `1` makes a missing or refused `X-Firebase-AppCheck` token a 401, default off = one logged warning; `/health`, `/healthz`, the tick exempt).
## Local rules

Sign-in (`tilo_api.firebase_auth`, `deps.get_current_principal(request)`, `tests/API_SIGNIN.md`, BQ-SIGNIN-2/3/6): `Authorization: Bearer <Firebase ID token>`, RS256 against Google's securetoken keys for `TILO_FIRESTORE_PROJECT`/`GOOGLE_CLOUD_PROJECT`, only Google (email verified) or anonymous, else a fixed 401; `full_session` only for Google, an anonymous `demo_session` is replay-only (BQ-SIGNIN-10) and stores nothing durable (`tilo_api.ephemeral`, BQ-DEMO-EPH-1: the store, writer, outbox, artifact, archive, upload and people seams give it a per-session in-memory bundle by the verified uid, idle TTL 30 min, caps fail closed 429/503 `demo_capacity`; no schedules, 403 `demo_schedules_unavailable`), verified once per gated request; `X-Tilo-Channel: mobile_web`; dev mode never reads a token. Live models only via `provider_mode` -> `deps.router_for_mode` (replay_only wins; `TILO_JUDGE_LIVE=1` is the user's, never set in code). SEC-16 (`tilo_api.spend`, `config/spend_caps.yaml`, `tests/API_SEC_16.md`): deployed, the gate rate-limits a judge by verified uid (429 `rate_limited`); `deps.get_work_mode` refuses new work at the uid's lifetime cap (403 `spend_cap_reached`) or with either switch set (503); live needs `deps.get_spend_cap_ledger` wired (503 until then, so replay), with per-unit `SpendGuard` wiring (BQ-SEC16-1).
