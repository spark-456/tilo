Contract rules that JSON Schema cannot express (id cross-references inside one document) must be numbered in a contracts/<name>.rules.md (PG-xx in plan.rules.md, WE-xx in layout.rules.md) so the deterministic validators enforce them. In the P0-02 review (2026-09-25) card.schema.json described "safe_default must be one of the options" only in prose, and it also allowed an irreversible option as the timeout default; no card rules file existed.

**Why:** Prose-only rules in a frozen contract get skipped by validator builders; safe defaults and gates are safety-relevant (PRD 10.3, 10.4).

**How to apply:** For each schema, mutate a valid fixture to break every cross-reference its descriptions claim, and check that the schema rejects it or a rules file names the rule. To test drift without copying node_modules (pnpm symlinks break when copied), import scripts/contracts_codegen.py, point c.ROOT and c.CONTRACTS at a scratch copy and call c.main(["check"]). Also print each invalid fixture's errors to confirm it fails for exactly the rule in its name (import contracts_codegen, iterate c.fixtures(c.load_schemas()), call c.validate; set PYTHONIOENCODING=utf-8 on Windows or cp1252 print crashes on fixture text). The card fix (commit 3d4b3c4) added contracts/card.rules.md CR-01..CR-05 and a schema-level "only gates offer irreversible options" rule; that is the accepted pattern for schema-inexpressible rules: number them, mark "validator" vs "schema", and point to the P1 validator.

Event contract (P0-03, reviewed 2026-09-25): registry-only rules are EV-01..EV-12 in contracts/event.rules.md, checked by scripts/contracts_events.py (event_problems, stream_problems). Fast probe: import contracts_codegen + contracts_events, call event_problems on each fixtures/events/{invalid,registry/invalid} file and print the first problem. The generated header includes a sha of the parsed registry.yaml and each parsed schema (json.dumps sort_keys), so a semantic edit trips drift but a comment or whitespace-only edit does not (by design). Probe with a description change, run from the scratch dir (PY_OUT/TS_OUT are relative to cwd), also copy config/ into the scratch root. Final P0-03 pass (b9b193e): registry = exactly the 70 PRD 9.5 types; check with yaml load of registry["types"].

Generated tilo_contracts pydantic models do NOT enforce JSON Schema if/then conditionals (e.g. providers prices: status "set" with null prices validates). Consumers that validate only via the pydantic model miss those rules. Seen in P0-04 review (2026-09-25): config loader accepted status: set with nulls and price() fell back to a bare assert (None prices under python -O). Probe: mutate the config to trip each if/then branch and load it through the consumer.

Provider adapters (P0-05, reviewed 2026-09-25): check that capability features are actually *requested*, not just passed back. The first P0-05 build had "JSON mode / structured output" tests that only checked that the mocked response text parsed as JSON. GenerateRequest had no response-format field and neither adapter set response_mime_type/response_schema or response_format. Probe: grep src for response_format/response_mime_type and check that the test asserts on the outgoing request body. Also: providers.schema profile lacks base_url/api_key_env (a contract blocker), so the NIM loader test fails until the contract owner adds them. Second pass (7d1e451): builder marked that acceptance test xfail (a weakened test; watch for this). Also check the LIVE semantics: RecordReplayProvider only goes live when TILO_RECORD=1, so LIVE=1 alone still replays and live use is impossible. EFF-01 means LIVE=1 enables live calls and TILO_RECORD=1 only adds writing. Third pass (26a844d): xfail removed and LIVE semantics fixed, but the NIM loader test still fails on the missing contract fields and the factory raises NotImplementedError for openai_compat. This stays FAIL until the contract owner adds profile base_url/api_key_env; the builder cannot fix it. Smaller issues to recheck later: in live mode RecordReplayProvider.stream calls generate (no real streaming) and capabilities() returns set() instead of delegating.
