Traps found while building P0-02 (2026-09-25), still true while the codegen setup is unchanged:

- The FR-WLD-02 drift test runs `just contracts-check` in a sandbox copy that holds only contracts/, packages/contracts-*, scripts/ and root build files — no config/. Anything contracts-check reads outside that set must be optional.
  **Why:** a required config/ check made that acceptance test fail.
  **How to apply:** P0-03 (event registry) and later checks must not need config/ or services/ to pass in that sandbox.
- json-schema-to-typescript 16 turns `prefixItems` + `items: false` into `never[]`; the codegen rewrites tuples to draft-07 `items: [...]` for TS only. Check the generated TS after any new tuple or unusual keyword.
- Dropping or adding a field means rewriting every fixture of that contract, invalid ones too, or they fail for the wrong reason. Afterwards run `pnpm exec biome format --write contracts`, because json.dumps layout differs from Biome.
- Profiles have no cost field: cost rank is derived from config/prices.yaml (ADR-0002). Card answers live in the answering event and the Decision, not on the card.
- The test-writer's files were formatted by an older ruff from pre-commit; P0-02 moved pre-commit to the uv.lock ruff. If fmt-check fails on fresh test files, reformat them and list them as formatting-only in tests_modified.
- Every file in fixtures/<name>/invalid/ must fail the JSON Schema itself (FR-WLD-02 test). A rule that compares two values (for example a card's safe_default naming an option id) can't have a fixture there. Number it in <name>.rules.md as "validator" and say that the P1 validator's tests cover it.
- Security review (P0-02 round 2) failed shapes that config could weaken. The T3 modifier list could be emptied, policy conditions could be set false, authz.ref was not tied to `by`, and a non-gate card could default to an irreversible option. **How to apply:** in any new contract, pin safety lists with minItems or const, and bind an id to its discriminator with if/then. Anything applied without a person (timeouts, defaults) must be reversible in the schema.
- Security review round 3 found that a gating rule keyed only on capability, like "gate_type none", let a T3 or irreversible action through. It also found that "only gates are authorisations" missed consent cards. **How to apply:** gate on risk tier and irreversibility as well as capability. Treat every grant (a connection, scopes, a policy) like a gate: no Director delegation and a `hold` default. A rule keyed on an id (hold) must hold for every item with that id, not just one (`contains`), or a duplicate id defeats it.
- Security review round 4: an option that triggers an action (a gate's approve) needs a fixed id from a closed set, not an id or label a model writes. Its flags must be tied to the thing it acts on with if/then (approve.irreversible equals gate.irreversible). Otherwise a "send" option can be marked reversible and suggested. **How to apply:** for any answer that authorises, fix the ids (allOf of contains/minContains/maxContains gives each id at most once) and state which id opens it.
- Security review round 5: fixed ids were not enough. The person taps the *label* (WhatsApp shows only labels), so an authorising option needs its label fixed by id too. Also, card fields copied from elsewhere (gate tier, irreversible, recipients) need a cross-reference rule back to their source. **How to apply:** never argue "the engine reads ids, so labels don't matter"; fix the labels. For cross-document rules, use `fixtures/<name>/crossref/{valid,invalid}` (contracts-check skips subfolders) plus a named reference-check test.
- json-schema-to-typescript drops a named alias (for example CardOptionId becomes string) when a `$ref` has a sibling `description`. Put the text in the parent's description instead.
- Security review P0-03 round 6: once history decided the level in force, nobody checked *who* wrote each history entry, so another user could raise a revoked policy back to L2, and a policy's `owner` label alone let anyone create one "as" the owner. **How to apply:** whenever a record's contents decide authorisation, bind every author stamp in it (created_by, changed_by, each history[].by) to the role the PRD allows (PRD 10.1: only the Owner creates/changes policies), and bind the change event's `authz.ref` to that owner, not only `authz.by` to "person".
- Parallel branches pick BQ ids on their own: P0-08a and P0-02 both used BQ-12. Check other feat/* branches (`git show <b>:docs/open-questions.md`) before choosing a new id. P0-03 used BQ-20 to BQ-26 and ADR-0005, leaving BQ-18/19 and ADR-0004 for P0-04 in flight; the orchestrator may renumber.
- json-schema-to-typescript turns a root-level `allOf` (even of pure if/then) into `{[k: string]: unknown} & X1`. Keep conditionals in one root if/then/else, nesting further if/then inside `then`/`else`.
- A generated TS header must never contain `*/` (a glob like `contracts/**/*.schema.json` closed the comment and broke tsc).
- The P0-03 tests validate one sample event (authz by person u_owner, data {}, target B0001) for every side-effect type. So per-type rules on authz.by or on data cannot live in event.schema.json; they go in the registry (authz_by) and the validator rules (EV-04). Test-writer minimal payloads (question.answered = {answered_by}) also fix which data fields may be required.
- Event rules that need the registry, other fields or other events are EV-xx in contracts/event.rules.md, checked by scripts/contracts_events.py. Registry-only violations go in fixtures/events/registry/invalid/evNN_*.json, because fixtures/events/invalid/ must fail a schema.
- Security review P0-03: a side-effect record (outbox entry) must name *what* it sends, not just who and to whom. Without a pinned item (artifact_ref with version) and destination (thread/folder), the connector fetches content from outside the contract, and a redraft after approval or during an L2 undo window goes out under the old authz. **How to apply:** every authorised action carries the pinned version, and every record along the chain (card, reservation event, policy event, outbox entry, transfer event) repeats it with an equality rule (CR-12, OB-05). Compare artifact_id+version, never labels.
- Security review P0-03 round 2: pinning *what* is sent was not enough; the chain must also pin *who authorised it*. OB-01 had said "authz equals that event's" where "that event" read as approval.requested (authz null), and the crossref check never compared authz, so an unapproved gate or a policy send stamped as a person (HR-7) passed. **How to apply:** name the exact authorising event and answer (approval.resolved option approve, same gate/card/outbox ids; or policy.applied with ref = policy_id), require equality of the whole authz object on every downstream record (outbox entry, data.transfer), and write invalid crossref cases for: never answered, hold, another gate, another person, Team Lead instead of person, policy-as-person, person-as-policy, transfer stamped differently. Opaque connector ids (destination) allow only `[A-Za-z0-9_-]`: `:`, `/` or `.` admits URLs and domains.
- Default `uv run pytest` includes the @slow drift tests; the whole suite takes ~95 s on this laptop, near check-fast's 2-minute budget. Slow P0-03 cost is the test lib re-parsing registry.yaml per parametrized test.
- Security review P0-03 round 3: OB-05 tied the outbox entry to "what the gate card showed", and the unattended policy (Autopilot) path has no card, so recipients, connector, destination, tier and undo window were unchecked there. **How to apply:** every binding stated against a person-facing artefact (a card) needs a twin for the no-person path. Bind it to the event that authorised it (`policy.applied` records what was assessed, but never recipients) and to the policy's scope, and give each field its own crossref case. Also, one invalid case must break exactly one rule: split "out of scope" (OB-01, policy vs event) from "differs from what was assessed" (OB-05, entry vs event).
- Security review P0-03 round 4: a policy stands in for a person only as far as its level says. L2 ("instruction is approval", PRD 10.4, FR-HIL-05) needed a link to the owner's own instruction, and without it L2 worked like an uncapped L3. **How to apply:** for each autonomy level, name the act by a person that the level still requires and link to it (`policy.applied.instruction_id`). Bind it to the same world, the owner as actor, an earlier time and the same destination. Also bind the policy to the world's owner and to `created_by.at <= authz.at`, and cap every level that acts without a person (per_day at L2 and L3).
- Security review P0-03 round 5: a link to "the person's own act" is only as strong as the channel that act arrived on, and one act must not authorise twice. The L2 instruction accepted any `channel.message_in`/`world.requested`, including email, whose sender is unauthenticated (PRD 10.3: email answers questions only, gates need sign-in), and one instruction could open any number of sends, even after Undo. **How to apply:** whenever a record stands for a person's consent, restrict it to channels with a known sender (web/mobile_web signed in, WhatsApp bound number) with a case per excluded channel, and make it single-use (unique across the world's authorising events, a cancelled use counts). Cross-event uniqueness needs a crossref slot for the earlier events (`earlier_applied`). Invariants for P4 are collected in docs/security/p4-policy-invariants.md; add a row there with every new OB/CR/EV/PG rule.
- Security review P0-03 round 6: expiry was bound but revocation (its owner-driven twin) was not. `policy.changed` `revoked` could carry L2, and OB-01 read only the policy record's current `level`, so a send after a revocation or Stop all passed, once the level had been raised again. **How to apply:** for every grant that can be withdrawn (policy, connection consent, budget), check it against the state in force at `authz.at` (the last history entry at or before it), not the current record. Force every withdrawal event to a non-authorising value in the schema. Tie the record to its history (the level equals the last entry's; history is ordered and never empty). Add cases for "withdrawn before", "withdrawn then re-granted" and a valid "sent before withdrawal".
- Security review P0-03 round 8: "entry authz equals the approval's authz" proved nothing about *who* approved. Each path's authoriser must be checked against PRD 10.1's role table (owner; Approver only if assigned; Team Lead only in an owner-assigned domain and if a policy allows; Viewer never) and channel controls (PIN for T3 on WhatsApp, SEC-06). **How to apply:** for every authorising event, record who may authorise it (named on the reserving event, copied from owner-made records) and add one crossref case per role that must be refused. Fixed with ADR-0006, `team_lead.schema.json`, `policy.team_lead_domains`, `approval.resolved.pin_verified`.
- Python `Path.write_text` on Windows writes CRLF. Write fixtures with `write_bytes(...encode())`, or strip `\r` afterwards, then run `pnpm exec biome format --write contracts` after any scripted fixture rewrite.
- P0-02b: python-jsonschema's `pattern` uses re.search, so `$` also matches before a final "\n" ("ABC\n" passes `^[A-Z]+$`); pydantic's rust regex doesn't, and it rejects lookarounds. A Hypothesis "non-matching never validates" test will find it. **How to apply:** add `"not": {"pattern": "\n"}` to anchored string fields that guard secrets or URLs.
- P0-02b: datamodel-codegen turns `format: uri` into `AnyUrl` and silently drops pattern/maxLength; the codegen now passes `--type-mappings=string+uri=string`. Check the generated field after adding any new `format`.
- Any additive bump breaks tests that pin `x-version == "1.0.0"` (FR-WLD-02 test now accepts 1.x.y). Test-writer fixtures may carry real model ids (a NIM Gemma id did): replace them with fake ids.
- Python `Path.write_text` on Windows writes CRLF. Write fixtures with `write_bytes(...encode())`, or strip `\r` afterwards, then run biome format.
- Security review P0-03 round 9: round 8 made the Team Lead's domain an owner-made record but left the Approver a bare user id on `approval.requested`, so whoever the harness named (a Team Lead outside their domain included) could open a T3 gate. **How to apply:** apply one rule to every role grant, not just the one under review: each is `{who, assigned_by: {by, at}}`, checked `by == world owner` and `at <= authz.at`, with invalid cases for "someone else assigned", "assigned after the answer" and "self-assigned by a lesser role". Also make the reference check enforce per-event stamps (EV-04/EV-06) itself, or restamping two records together passes it.
- Rewriting a hand-formatted schema with json.dumps expands every one-line `{ "$ref": ... }`, and biome keeps objects expanded: edit schemas textually (Edit tool); json.dumps + biome is fine only for fixtures already in expanded form.
- Any additive bump breaks tests that pin `x-version == "1.0.0"` (FR-WLD-02 test now accepts 1.x.y). Test-writer fixtures and test files may carry model-family ids (a NIM Gemma id; `gemini-flash` as a fake authz ref in CC-SH), which fail `lint_model_ids.py` in `just check`: rename them to a fake id and list the file in tests_modified.
- CC-SH: datamodel-codegen drops a float `const` (0.7 became plain `float`), so repeat it as `minimum`/`maximum`. An inline array inside `anyOf` becomes an unprefixed alias named after the property (`Worlds`), so make it a named `$defs` entry. When a test wants a root title other than the PascalCase file name (`AgentsConfig` for agents), add it to `ROOT_NAMES` in the codegen.
- BQ ids also appear in commits that never reach docs/open-questions.md (P0-06 used BQ-53 to BQ-55). Before choosing a new id, check `git log --all -G "BQ-NN"` as well as the branches.
- Code review P0-03, after issue #21: a WhatsApp button tap arrives as `channel.message_in`, so Hold on a gate card counted as an L2 instruction. Excluding every card answer would have broken PRD 11.2, where the typed answer to "What should I say?" (a question card) is the instruction. **How to apply:** before cutting a whole class out of an authorising path, check that the PRD's own flow doesn't rely on it. Record facts set by the channel (`card_kind`, `option` from the button payload), not verdicts, and admit only typed words. A review item deferred in an issue comment still needs a BQ row, a PI row and a filed follow-up issue, or the next review fails it. The codegen accepts `$ref` only into `$defs`, so move a shared enum there first (card `kind` became `$defs/kind`).
- CC-SH review: a stored answer that is reused later (a Decision) must have its answerer's authority checked again where and when it is reused (the reusing world's owner; the Team Lead record still exists, same domain, assigned by that world's owner before the answer). Checking only at write time let removed Team Leads, other owners' worlds and Approvers through. **How to apply:** for anything that stands in for a person later (Decisions, policies, cached approvals), write the reuse-time check and add crossref cases for removal, another owner's world and each role that must be refused.
- CC-SH review: a denylist regex for URL credentials (`not ^scheme://[^/]*@`) missed `//u@h`, `https:\u@h`, `https:u@h`, a leading space and `?access_token=`. **How to apply:** use an allowlist of closed shapes for any exported string that could hold a URL. Test-writer tests may reuse one sample value across enum values (a web URL for every `kind`), so shapes may have to stay kind-independent.
- CC-SH review round 3: role ids (`tl_`, policy ids) are mutable indirections. The owner can put another person behind `tl_security` and leave `assigned_by` as it is, so a reuse check that binds only the id lets the former person keep answering. **How to apply:** a stored answer records the *person* too (Decision `answered_by.user`), and the reuse check compares it with the current record. Shape allowlists never catch a bare token (`ya29...` is a valid file name), so any string that leaves Tilo also needs a rule that the secret redactor runs before it is written and exported (MF-06).
- Every new rule needs a *valid* fixture as well as invalid ones (a reviewer failed CC-SH for this). Extra valid event cases go in `fixtures/events/valid/<type>--<case>.json`.
- CC-SE review: issue #7 and SE's stand-in asked for every credit cap to be nullable ("null = no cap"). I followed the request, but PRD 14.1/FR-MTR-04 (Must) requires per-run and per-user daily caps, and BQ-42 only decided the org exception. A reviewer failed it because nothing but the US$25 kill switch would stop a runaway run. **How to apply:** when a builder issue or test asks to make a limit optional, check the PRD Must rows and the decided BQ scope first. Allow null only where a decision says so, and use a separate `$defs` entry for it (`cap` vs `org_cap`), not one shared nullable type. Fix the test-writer test that asked for null and list it in tests_modified.
