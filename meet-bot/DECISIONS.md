# Decisions

One line of reasoning each. Newest at the bottom.

- **Lives in `meet-bot/` inside the Tilo repo, standalone** (own `pyproject.toml`, no `uv` workspace membership): keeps it out of Tilo's `just check` gate and its provider/model-id rules, which this prototype deliberately does not follow yet.
- **Host CLI is stdlib-only and re-runs itself inside Docker** (`TILO_IN_CONTAINER=1`): one command set on Windows/Mac/Linux, no host installs, no shell scripts.
- **Entrypoint is Python, not a shell script**: a Windows checkout with CRLF endings would break a `.sh` file inside Linux.
- **Named Docker volume for the browser profile, not a bind mount**: Chromium profiles on a Windows bind mount hit NTFS permission and SQLite locking problems; `profile/` is still in `.gitignore`.
- **`login` runs plain Chromium, not Playwright-controlled**: Google is far more likely to refuse sign-in in an automated browser; the same profile is then reused by Playwright.
- **noVNC bound to 127.0.0.1 only; VNC has no password**: the session shows a signed-in account, so it must not be reachable from the network.
- **Container runs as non-root `pwuser`**: PulseAudio refuses to run as root; Chromium still uses `--no-sandbox` (standard in containers).
- **Bind-mount the whole project to `/app`**: agenda, outputs and debug screenshots land on the host, and code edits need no rebuild.
- **Meeting created via `meet.google.com/new`; `--api-create` is a stub that says it is not implemented**: the Meet REST API needs a Google Cloud project and OAuth consent that a human must set up; stretch goal skipped.
- **Camera/mic off by clicking "Continue without microphone and camera" or "Turn off ..." buttons**: no media device is ever opened; no fake devices or permission flags.
- **Captions parsed from raw HTML in Python, not in the page**: the parser is testable offline; the page only ships `outerHTML` (throttled 250 ms via MutationObserver, plus a 1 s re-attach timer).
- **Parser finds speaker blocks by text shape (name line + speech lines), never class names**: Meet's class names are obfuscated and change.
- **Caption fixtures are synthetic**: no live meeting was available; `SAVE_CAPTION_SNAPSHOTS=1` records real ones for the first live test.
- **Utterance settles after 2.5 s unchanged or when its block leaves the screen; growth after settling emits only the new suffix**: avoids duplicate text when Meet keeps a block visible.
- **Bot's own captions ignored by name ("You", `BOT_DISPLAY_NAME`, name read from the account label)**: its mic is off, so this is a safety net.
- **Model access behind an `LLM` protocol in `brain.py`; the model gets the transcript as JSON data and is told it is untrusted**: swappable provider, and transcript text cannot instruct the bot.
- **Chat policy is code, model wording is optional**: the model may suggest text, but code decides whether to speak, and uses the model's sentence only if it is one short sentence about the trigger; otherwise a template.
- **Intro message does not count toward the 4-message cap or the 5-minute gap**: it is a disclosure, not a nudge.
- **Fair share = sequential window laid out in agenda order** (items without minutes split the leftover time): "untouched after its fair share" fires when an item is still `not_started` after its window ends.
- **Action-item nudge needs the item to look incomplete in two consecutive brain runs**: avoids nagging over a half-formed item.
- **Trigger priority: time warning, then agenda gap, then missing owner/due; each subject nudged once**: the time warning is the most useful and needs no model.
- **Time warning skipped when the planned meeting is 10 minutes or shorter**: it would fire at the start.
- **Agenda statuses only move forward; decisions and action items are unioned across runs; owner/due are never erased**: a forgetful model reply cannot undo tracked state.
- **Model outage never stops the meeting**: 429/5xx retry with backoff (2, 4, 8, 16 s), then the step is skipped, the interval doubles up to 4x, and the time warning still works.
- **Default model chosen by listing models and taking the highest plain `gemini-N-flash`; fallback `gemini-2.5-flash`**: "current Flash" without hard-coding; unverified against a real key.
- **Bot leaves when the meeting ends, when everyone else left for 60 s (only after someone else was seen), after 15 min if nobody ever joins, or at `MAX_MEETING_MINUTES`**: guards against a bot sitting alone forever.
- **No study of the reference repos (recallai, attendee) beyond prior knowledge**: web access was not used; approach (persistent login, caption region observation) follows what those projects are known for.
- **Host via /new lands straight in the call**: `join` checks for "in call" first and closes the "Your meeting's ready" card (found in the first live run).
- **Bot starts (intro, clock, brain, chat) only when required people are present**: required names come from the agenda `Required:` line, `--require`, or `REQUIRED_PARTICIPANTS`; with none, any other participant opens the gate. The intro chat waits for the gate too.
- **Auto-admit is opt-in (`--auto-admit`), optionally limited by `ADMIT_ALLOWED_NAMES`**: admitting strangers by default would be unsafe.
- **Direct questions get their own fast path and budget (default 12 replies, 6 s apart), separate from the 4-message nudge cap**: nudges stay rare; answers must be timely.
- **`ANSWER_MODE=questions` by default**: live captions garble the assistant's name ("Tilo" -> "Heart", "Tyler"), so any question is offered to the model, which replies only if the meeting info answers it.
- **Audio recording is opt-in and disclosed in the intro chat line**: it is a recording of other people; it stays in `out/` and is sent only to Gemini if `retranscribe` is run.
- **Live finding (2026-09-29): Meet's captions are the weakest link**; on the same recording Gemini transcribed far more accurately. A hybrid or audio-based live transcript is the recommended next step.
- **Project knowledge is plain keyword retrieval over local files, URLs and chat text**: fast, offline, no extra API; URLs must be public http(s) (private/loopback refused) and everything is passed to the model as untrusted data.
- **Typed chat is a first-class question route**: exact text, no speech errors; pasted non-question chat text becomes answerable context.
- **Streaming STT via ElevenLabs Scribe is implemented behind `--stt elevenlabs`, untested against the real service until a key exists**: protocol taken from the vendor docs, tested against a fake server; `stt-probe` measures the real service before we rely on it. Realtime diarization and free-tier API access were not documented (only claimed in vendor chat), so speaker ids are used when present and caption speakers otherwise.
- **The key is only ever read from the environment and sent as the `xi-api-key` header; errors are redacted**.
- **Voice architecture v2 is in `docs/VOICE_ARCHITECTURE.md` (2026-09-30)**: our own end-of-turn and floor control in front of any voice. Gemini Live is the target voice if `live-probe` (X4) shows it is instant; the streaming cascade is the fallback. The user confirmed that the bot is part of the Builder Cup submission and that free-tier Gemini data use is fine.
- **`live-probe` speaks the raw Live WebSocket protocol, not the google-genai SDK**: same pattern as the Scribe client, testable against a fake server, and independent of SDK version drift. The AI Studio key is sent only in the `x-goog-api-key` header and redacted; Live model ids live in `bot/config.py` (`LIVE_MODELS`).
- **Direct answers run on `FastLLM` (`bot/llm_fast.py`, VA-01): one long-lived async client, a 2.5 s first-token deadline, one immediate retry on a fresh client, and a 429 is `Busy` with no sleep**: the old sync client inside `to_thread` could sit 12 s on a cold or stalled connection; now the worst case is about 5 s and every attempt is in `latency.jsonl` (`model_attempt`). `Busy` subclasses `LLMUnavailable`, so callers that already handle an unavailable model handle it too.
- **`_keep_warm` is deleted; the connection is warmed on intent instead** (`FastLLM.prewarm()`, a free `models.get`, at most once per 10 s, at join and when a question is heard): pinging every 5 s from another thread never warmed the connection the replies actually used.
- **`FAST_THINKING` (off | minimal | low | medium | high) sets thinking, not the model name**: `off` sends `thinking_budget=0`, anything else `thinking_level`. A 3.x fast model needs `minimal` or more, so X1 decides the final pair.
- **Every model id now lives in `bot/config.py`** (analysis default, fast default, ElevenLabs TTS and Scribe ids), guarded by `test_VA_01_no_model_id_literal_outside_config`. VA-INT moves them on into Tilo's `config/`.
- **A question is handled by the start time of the utterance that carried it, not by its text and not by an id (VA-02)**: a live partial and its final are two objects for one utterance, so ids cannot match them, while matching on text alone dropped the 29 Sep repeat. A question counts as already handled only if its utterance started at or before the one tried; a person asking the same thing again starts later and is attempted again, still inside the 6 s gap and 12-reply budget. The partial gets the time it was first seen, which is never earlier than its final's start.
- **Every typed chat message is addressed to the assistant** (architecture 3.5): no question mark needed. The model answers, says `[[NO_ANSWER]]` / `[[UNCLEAR]]` (mapped to fixed lines) or returns null for a statement or pasted note, which stays silent. Chat that is not a question is still stored as project context.
- **Fallback lines are spoken and posted only for addressed questions; a null reply to an addressed question that contains "?" counts as no answer**: unaddressed questions are never answered out loud. A busy or failed model on an addressed question says "I couldn't get that just now." Fallbacks count against the direct-reply budget, so they cannot spam.
- **Scribe keyterms: bot name, required and present participants, agenda titles, then project terms (2+ mentions, stop-words removed), 50 at most, each up to 40 characters**: new participants apply at the next Scribe connection (the terms are in the URL).
- **The Meet page is used through a priority scheduler with short critical sections (VA-03, `bot/ui.py`)**: mic > chat post > chat read > admit > People, each section one find, click or fill, and every sleep or poll outside it. A mic request therefore waits for at most the one primitive already running (measured on a fake page: 0 to 30 ms, acceptance 50 ms); true pre-emption of a running Playwright call is not possible. The old code held the lock through a 0.8 s sleep, which is where the ~1.75 s unmute wait came from.
- **`MIC_POLICY=open` is the default**: the bot unmutes once when the meeting starts for it and every status check (15 s) re-unmutes if someone muted it; the virtual mic is digital silence unless the bot speaks, so an open mic sends nothing. `conversation` keeps the old unmute and mute per answer. The bot stays muted until the meeting has started, as before.
- **Replies are delivered from their own task and the People check is a task (VA-03)**: the main loop (tick 0.1 s, was 0.5 s) keeps reading captions and chat while a reply is spoken or the People panel opens. A direct reply is booked with the chat policy when it is queued, so a second question cannot slip past the 6 s gap while the first is still queued. The chat copy of a spoken answer is posted after the first sound.
- **A People read that finds no rows is treated as unreadable, not as an empty room**: its two steps no longer hold the UI, so a chat post can replace the panel in between; the bot itself is always listed, so zero rows means the wrong panel.
- **One row per human turn in `turns.jsonl`, all marks relative to the end of the human turn (VA-04, `bot/trace.py`)**: the marks are the architecture's list plus `barge_start` (so a barge-in stop time can be computed); a turn that never reached a stage simply lacks that mark. `route` is `instant` or `model`; chat-only delivery shows as `outcome=chat_only`. The end of the human turn is the last loud audio frame when the meeting audio is captured, the read time for typed chat, and an estimate (detection time minus the idle wait) otherwise; the row says which (`speech_end_source`).
- **Percentiles are linear interpolation between the closest ranks**: exact and reproducible on small samples (p50 of 1..10 is 5.5).
- **`audit` needs only `bot.wav` when `turns.jsonl` has audio-clock anchors, and both recordings otherwise**: with anchors it times each turn's end to the next bot sound; without them it detects speech bursts in both files (RMS of 10 ms steps against the same level the voice check uses, bursts closer than 0.35 s merged) and pairs each bot burst with the latest human burst before it. Its resolution is one 10 ms step; `audio_clock.json` (start times of the two captures, set within tens of ms of each other) removes most of the offset between the files.
- **Both captures use `parec --latency-msec=20`**: the default buffer would add its own delay to every measurement and to barge-in detection.
- **Conversation mode (CV-01, user request 2026-10-02): when Tilo is spoken to, the model answers anything, in one or two plain sentences; overheard talk keeps the old meeting-facts-only rule**: the quick prompt has two branches on `addressed_to_assistant`. Meeting and project facts are still never invented (`[[NO_ANSWER]]`), general knowledge is the model's own with a brief "not sure" instead of a guess, and a bare "Tilo" gets "Yes?". Unaddressed questions are still answered only from the notes or project files, so Tilo never joins people's small talk.
- **Addressed = typed chat, or the name (or a common mishearing: tillo, tylo, teelo) opening or closing a sentence, question mark or not; "I told Tilo about it" does not count**: the name must be the first word (after hey, okay, so...) or the last. For 15 s after Tilo answers, a question or request (a question mark, or a lead word such as tell, explain, why, and) needs no name. A statement said by voice waits 0.8 s longer than a question before it is treated as finished, so a pause mid-sentence does not trigger an answer.
- **A reply too long for two sentences is cut to the first sentence instead of being dropped, and the default direct-reply budget is 40 (was 12)**: a conversation would have used up 12 in a few minutes. The 6 s gap stays.
- **Fast model defaults to the analysis model, with a 404 fallback, and prewarm turns itself off when the key cannot call `models.get` (found in the first live meeting, 2026-10-01)**: `gemini-2.5-flash-lite` returned 404 ("publisher model not found") for the Express key in asia-southeast1, so no direct question was answered. A configured `FAST_MODEL` that 404s now falls back once to `GEMINI_MODEL` (or the default) and stays there; `models.get` returns 401 for API keys, so prewarm stops after the first failure instead of failing on every question. X1 still decides whether a faster model exists for this key.
- **The free Express key is throttled, so answers come first (2026-10-02 live finding)**: the same tiny call took 0.7 s, 1.3 s, 5.5 s, 14.8 s and once failed with 429 after 12.6 s, so the "12 s model calls" are server-side throttling, not our connection. The meeting-notes loop is held back while a question is being answered and for 30 s after the last one (`analysis_allowed`), and the first-token deadline is `FAST_FIRST_TOKEN_SECONDS` (default 6, was a fixed 2.5 s that cut answers off). A key with a healthy quota (an AI Studio key, free) would fix the root cause; that needs a Studio backend and is the user's choice.
- **Robust conversation for bad microphones (CV-02, from the 2026-10-02 live meeting)**: Scribe and Meet's own captions both heard "tell me a joke" as "tell me, John" and "tell me your joy", with no name or question mark, so nothing was answered. Now: (1) when exactly one other person is in the meeting everything they say (3 or more words) is addressed to Tilo; (2) the conversation window is 30 s from the last exchange, not 15 s from the last reply; (3) the prompt tells the model that words are often misheard (joke as joy, job, John) and to answer what was most likely meant, with `only_person_here` in the payload; (4) a live partial and its reworded final within 8 s and 0.8 similarity are one question, not two; (5) a voice the plan refuses is remembered for 24 h in `out/.tts_state.json`, so only the first-ever reply pays the slow failing call; (6) the People panel is not read while a reply is being delivered, because opening it covered the chat being typed into (the chat copy took 15 s). Verified on the real model: "Please, tell me your joy." gets a joke, "Yes." gets nothing.
