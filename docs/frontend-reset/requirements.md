# Frontend reset: proposed requirements

Status: **proposed addendum, awaiting the user's approval** (asked 2026-10-03). The PRD is read-only, so these live here. Two new families: `FR-KIT-*` (the world art system) and `FR-UX-*` (the app experience). On approval they count as requirement IDs in the ticket loop, with the acceptance test as the definition of done. They add no contract change except one additive schema (FR-KIT-02). Background: [art-facts.md](art-facts.md). Plan: [README.md](README.md). Tickets: [tickets.md](tickets.md).

Existing PRD requirements these build on and do not replace: FR-WLD-01, -04 to -11, UX-1 to UX-9, PRD 18.2 to 18.6, HR-1 to HR-7. Where one of those already says it, the ticket cites it instead of copying it.

## A. World art system (FR-KIT)

The goal: whatever task a person gives Tilo, the planner can describe it with parts from a published list, and the renderer draws a world that looks like it belongs to the same family as the original Metropolis designs, is readable at a glance, and is obviously about *that* task.

| ID | Requirement | Acceptance test | Priority |
| --- | --- | --- | --- |
| FR-KIT-01 | **Art bible, machine-checked.** The style rules in art-facts.md section 1 and 2 become `docs/design/art-bible.md` plus a lint over generated art: only token colours or `mix/dk/lt` derivations, no gradients, blur, filters or outlines other than the seam stroke, true isometric constants, 48-unit grid. | `FR-KIT-01 style lint`: render every kit part and fail on any off-palette colour, gradient, filter or non-30-degree face. Blind check by design-critic against the World Kit canvas passes. | Must |
| FR-KIT-02 | **Published kit manifest.** `config/themes/metropolis/kit.yaml` lists every roof, facade, body archetype, annex, prop, ground surface, vehicle and icon, with footprint, height range, compatible-with rules and the capability tags it serves. A JSON Schema (additive file `contracts/theme.schema.json`) validates it. This is the "published list" that WE-08 refers to. The planner prompt, the layout validator, the solver and the renderer all read the same file. | `FR-KIT-02 manifest valid`: schema passes; every entry has a renderer function and a gallery tile; the validator rejects a layout that names an unknown part or icon; a part added to the manifest without a renderer fails CI. | Must |
| FR-KIT-03 | **Capability atlas.** A written and data-backed map from *what work is* to *what it looks like*: at least 16 work domains and at least 70 capabilities, each mapped to a building archetype, icon, props and an agent-role colour, with a reason. Covers the PRD skills (8.2), the scenario backlog (4.3) and the 15 common buildings, and goes beyond them. Domain-neutral: no scenario names in the manifest (CLAUDE.md "no scenario-specific code"). | `FR-KIT-03 atlas coverage`: every capability resolves to a manifest entry; within a domain no two capabilities share the same (archetype, roof, facade, icon); a reviewer table lists 3 invented tasks per domain and the capabilities they use. | Must |
| FR-KIT-04 | **Building generator.** Composes any building from archetype + roof + facade + annex + icon + seed. Deterministic: same inputs give identical output. Every building draws in all states of PRD 18.5 (planned, constructing, operational, scaled, needs you, blocked, complete, archived) plus hover and selected. | `FR-KIT-04 deterministic render` and `FR-KIT-04 states gallery`: golden images for each archetype in each state within tolerance; two renders of the same spec are byte-equal. | Must |
| FR-KIT-05 | **All 15 common buildings** (Town Hall, Your Desk, Library, Browser Station, Workshop, Meeting Hall, Connector Post, Memory Vault, Treasury, Watchtower, Delivery Dock, Clock Tower, Agent Foundry, Mail Room, Expert Office), each in every state, each recognisable without its label. | `FR-KIT-05 common buildings`: 15 x 8 gallery goldens; a blind test (EV-G1 style) names at least 13 of 15 correctly without labels. | Must |
| FR-KIT-06 | **Agents.** Six ranks, nine role colours, every expression, a 2-frame walk, carried items (crate, scroll, parcel, backpack, book), crowd aggregation figure. Every `agent.*` event type maps to one expression or pose. | `FR-KIT-06 agent poses`: registry-driven test fails if an agent event type has no pose; gallery goldens for rank x role x expression. | Must |
| FR-KIT-07 | **Ground and infrastructure.** Plot surfaces (at least 6 variants: paved, lawn, yard, garden, water edge, industrial slab), roads, rail, footpath, pier and boat, bridges, islands, cloud cover, lifts and landings, gates (person-approved and policy-authorised with stamp, HR-7), trees and plants (at least 4 kinds), crates, carts, trucks, boats. | `FR-KIT-07 ground and infra`: gallery goldens; a gate rendered with `authz.by=policy` differs from one with `authz.by=user`; each bridge type is distinct in greyscale. | Must |
| FR-KIT-08 | **Variety guarantee.** A corpus of at least 40 plan/layout fixtures across at least 16 domains and every tier (outpost to metropolis) renders with zero unknown parts, zero overlaps, zero clipped labels, and at least 3 distinct silhouettes per world of 5 or more buildings. Generic fallback archetypes guarantee an acceptable building for any capability not in the atlas. | `FR-KIT-08 variety corpus`: automated render of the corpus; numeric checks above; contact sheet reviewed by design-critic. | Must |
| FR-KIT-09 | **Scale.** Tiers outpost, village, town, city and the 7-level metropolis tower with lifts. Level of detail: beyond 60 visible agents crowds aggregate (PRD 9.7). Static pieces are baked to texture atlases; only moving things redraw. | Covered by FR-WLD-10 perf budgets plus `FR-KIT-09 tier render` for all tiers and `FR-KIT-09 lod`. | Must |
| FR-KIT-10 | **Renderer uses the art.** `renderer.ts` draws every Frame with the kit; no placeholder diamonds or dots remain; the stage is never empty when the world has content. | `FR-KIT-10 no placeholders`: Playwright shot of `/world/:id` at seq N matches golden; canvas non-blank; grep test forbids the old `diamond()` helper. | Must |
| FR-KIT-11 | **Provenance.** All art is original or ported with permission (ADR-0003); every ported file is in `docs/licences.md`; no third-party brand assets, fonts or sounds (UX-8). | `FR-KIT-11 licence register`: CI lists ported files and fails on an unregistered asset. | Must |
| FR-KIT-12 | **Second theme loads with no code change** (PRD FR-WLD-15, raised from Could). Only if time remains after CP4. | A second theme manifest loads and renders the same layout in a different material palette. | Could |

## C. Constraints that apply to every ticket
- Honesty rules HR-1 to HR-7 hold: nothing animates without a recorded event; policy-authorised actions look different from person-approved ones.
- Fixture worlds are labelled "Fixture replay" or "Scripted demo" (HR-4). The K1 data is scripted.
- No scenario-specific code or manifest entries; scenarios are configuration (PRD 4.3).
- No new colours outside `design/tokens.json` except derivations; where a role is missing, ADR-0003's export-palette defaults apply.
- One filled primary button per screen (UX-1). Serious-moment copy follows PRD 18.4.
- Dev and CI make no paid calls; the web app runs on fixtures and the local API.
