# Bound meeting draft storage (FR-MTG-08 / FR-MEM-09)

`FirestoreDraftStore` uses the existing API store-door client and collection. An unbound adapter refuses reads and writes with 503. `bind(owner=..., source=..., expires_at=..., clock=..., before_publication=...)` returns a new request-local adapter; it never installs a source callback on the shared raw adapter.

The explicit owner follow-up caller derives source identity from the current organization, owner, world/run, meeting, minutes pointer, confirmation and complete snapshot digest. Its finite deadline is the earlier of stored `delete_minutes_after` and the artifact's stored `created_at` plus the existing artifact retention policy. Missing, invalid, future-created or expired authority refuses before generation. Fresh snapshots recheck artifact existence, screening, run and retention as well as meeting access and CAS.

After its original snapshot and CAS fence exist, the caller binds a new adapter with that authority. `FollowupPublication.drafts` carries that exact adapter into the scoped preview factory; the factory refuses a missing request draft port and never falls back to its raw store. Bodies and emit markers share the atomic retention envelope. Reads reject legacy rows, another source, another owner, expiry, and changed deadlines. Writes recheck authority after obtaining the SDK document reference, immediately before `create`; a post-write refusal leaves a retained row for cleanup. This is not a transaction across meeting, artifact and draft stores.

This caller is not activated production wiring. Called owner-erasure/meeting-retention cleanup, public dependency/budget wiring, exact integrated acceptance and whole-chain security review remain required. No new environment variable, store, client, provider call, dispatch or route activation is introduced. `meeting.minutes.enabled` remains false by default and public caller prerequisites remain closed.

Validation uses fake Firestore and replay providers: request-bound durable draft/card retry keeps one provider result and one T3/L1 preview with zero outbox entries. Invalid retention and post-generation deletion/run changes refuse publication; the shared raw store remains closed. Existing adapter tests retain atomic first-writer, tenant isolation, restart and unavailable-store assertions.
