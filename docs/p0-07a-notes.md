# P0-07a test notes (ambiguities and decisions)

Kept here, not in `docs/open-questions.md`, because this lane has no BQ ids allocated. The orchestrator may move
them into a block it allocates. Tests: `tests/repo/test_P0_07a_*.py` (static, offline, no docker, no cloud).

| # | Question | Default taken (and the test that pins it) | Source |
| --- | --- | --- | --- |
| 1 | Where do Dockerfiles live and what is the build context? | `services/<svc>/Dockerfile`, context = repo root (the uv workspace needs the root `pyproject.toml`, `uv.lock` and `packages/`), one root `.dockerignore`. Web has no image: Firebase Hosting serves the Vite build. | PRD 6.2, 6.3 |
| 2 | Five of seven services (harness, channels, connectors, browser, render) have no HTTP app or `/healthz` on `phase0-stack`; only api and sandbox-web do. | The builder adds a minimal ASGI `app` with `GET /healthz` inside each service's own package (module name free, must start `tilo_<svc>` and be named in the Dockerfile CMD as `uvicorn <module>:<attr>`), and adds `uvicorn` plus `fastapi` to that service's `pyproject.toml` and `uv.lock`. No scenario code. | PRD 6.2 (all seven are Cloud Run), 5.4 CP0 "hello endpoints" |
| 3 | Artifact Registry repo name: the brief said a `tilo-dev` repo; infra creates repo `tilo` and grants the deployer writer on that repo only. | Repo `tilo` (`asia-southeast1-docker.pkg.dev/<project>/tilo/<svc>`). Using another name would need a new infra grant. | infra/envs/dev/main.tf |
| 4 | Cloud Run service names. | `tilo-<svc>` (the names Terraform creates; the deployer's `run.developer` is per those services). Project `tilo-dev` is the project, not part of the name. | infra/modules/service |
| 5 | WIF accepts `refs/heads/main` only. | Every job is guarded `github.ref == refs/heads/main` and `github.repository == spark-456/tilo`; the `just deploy-dev` recipe dispatches with `--ref main`. | infra/modules/wif |
| 6 | May the workflow set public access (`--allow-unauthenticated`) or ingress? | No. `run.developer` cannot set IAM; Terraform owns invokers and ingress (public: api, channels, sandbox-web; the rest internal). The workflow only swaps the image and passes min 0, max 1..3. Also no `--set-env-vars`: runtime config is Terraform's, except `tilo-api` (`ignore_env = true`), whose `TILO_*` settings are set by hand per docs/routines-rollout.md. | infra/modules/service, SEC-12 |
| 7 | Identity-token smoke test. | NOT pinned. The runner is outside the VPC, so internal-only services (harness, connectors, browser, render) cannot be reached from it, and the deployer holds no `run.invoker`. The tests only require: curl `--fail` on `/health` (P0-07h; `/healthz` is reserved by Cloud Run on run.app), URLs taken from gcloud output, never hard-coded, after the deploy step. The builder decides how internal services are checked (for example `gcloud run services describe` Ready condition). User decision needed if a real HTTP check of internal services is wanted (it would need a widened IAM or an in-VPC probe). | PRD 6.5 ingress rule |
| 8 | Firebase Hosting deploy in the workflow. | Not done in CI: the deployer has no Firebase role by decision (infra/ACCESS.md section 8, item 3). `firebase.json` at the repo root (`public: apps/web/dist`, SPA rewrite) lets the user run the manual deploy. | infra/ACCESS.md (branch feat/P0-07b) |
| 9 | Workflow variable names. | `GCP_PROJECT_ID`, `GCP_WORKLOAD_IDENTITY_PROVIDER`, `GCP_DEPLOYER_SERVICE_ACCOUNT` (repository variables, not secrets); region is the literal `asia-southeast1`. | supervisor brief |
