# apps/web/src/park
## Purpose
The Park City web app (design handoff of 6 Oct 2026, `docs/web-app-rebuild-plan.md`), built beside the
old screens until the cutover PR. WEB-1a holds the tokens, fonts, typed fixtures and the `api/` layer.
## Contracts
- `api/index.ts`: `Api` (26 methods, one list `API_METHODS`), each returning `Promise<{ data, source }>`
  `parkApi(env)` (`api/select.ts`): no `VITE_TILO_API_URL` = fixture Api (`source: "fixture"`), a url =
  live Api, whose methods reject with `NotBuilt` until each endpoint exists. Never sample data as live.
- `api/fixtures/`: the prototype's data, typed (`api/types.ts`). `worlds.ts` and `index.ts` are
  hand-ported functions; every other file is generated by `node apps/web/scripts/park-fixtures.mjs`
  then `pnpm exec biome format --write apps/web/src/park/api/fixtures`. `fixtures.parity.test.ts` runs
  `design_handoff_tilo_web_app/design/tilo-app.js` in a vm and compares. `additive.ts` (hand-written, WEB-9c) holds
  `Decision.facts` and `Agenda.rules`, merged in `index.ts`; page logic stays free of scenario literals.
- `tokens/park.css`: handoff `tokens.css` scoped to `[data-park]`, night on `[data-time="night"]`,
  values verbatim (`biome-ignore format`), no motion. `tokens/ramp.ts` is the README type ramp. Themes (FR-WLD-15, BQ-WLD15-1/2): `config/themes/<id>.json` (role tokens a theme changes, day and night) -> `tokens/themes.{css,generated.ts}` by `just tokens`; `ParkApp` sets `data-theme={themeFor(prefs.theme)}`, unknown = Metropolis.
- `components/` (WEB-2): the README "Core components", named exports from `index.ts`, all styled by
  `park.components.css` (BEM `park-btn park-btn--primary park-btn--md`). CSS rules: every selector
  `[data-park] .class...`, literal values, `var(--token)` colours, no `transition`/`animation`; the
  marker `motion: restored in WEB-3 (BQ-WEB-3)` sits where the design moves (thumb, knob). A control
  that is a button is a real `<button type="button">`; `Toast` has no timer (`TOAST_MS` only);
  `Popover`/`Menu` share `Panel.tsx` (Escape on the document, backdrop, focus back to the opener).
- `dev/Components.tsx`: `/dev/components` (dev build only; a lazy route in `Root.tsx`), a day and a
  night `data-park` panel with every component; one filled primary button per panel (UX-1).
- Studio (UI-STUDIO-1, design/studio-v2): the DEFAULT theme. Colours are role tokens in `config/themes/studio.json` (day = light, night = dark; extra roles `priFill`/`onPri`/`priLip` = the primary button, `lime`, `lineStrong`, `focus`, `lilacSoft`/`lilacInk`; `heroFill` stays safe under the pages' white text); shape, Geist type and shadows in `studio/studio.css`, scoped `[data-park][data-theme="studio"]` (Metropolis keeps park.components.css). `time` pref: day | night | system (`store.timeFor`, follows prefers-color-scheme live); `studio/ThemeSwitch` (account menu) and Profile Appearance write it. Shared states `studio/States.tsx` (`EmptyState`, `Skeleton` still, `ErrorState`), styles in `studio/studio.components.css`. No motion in either file. UI-STUDIO-2 (BQ-STUDIO-2): `studio/Buddy.tsx` is the helper in STILL poses (idle, reading, talking, done) chosen by the caller from real request state; `chat/useQuickChat.ts` is one conversation over the real Quick path (`askQuick`, reading = call out, talking = new answer shown for `talkMs`, done after; nothing stored: the server keeps no Quick answers); `pages/Chat/` (route `/chat`, nav tab) puts the helper in a scene (`chat/Scene.tsx`, scene in `chat/displayPrefs.ts` storage with try/catch); `shell/TiloBubble.tsx` (every page but Chat) drags anywhere, arrow keys move it, place in storage; "Make it a world" hands the question to Home in memory (`chat/handoff.ts`), never the address.
- STUDIO-4: `pages/Needs/` (`/needs`, nav tab Needs you with the waiting count) shows one decision at a time from `getDecisions` (`Decision.card` = the served card fields): question, if yes / if no, cost ("Not reported" when none is served), exactly what is sent, Show me (`GET .../item` via `fieldsContext`); answers go through `app.decide` (typed answers and fields forms kept). `pages/Skills/`: gallery (`Gallery.tsx`), side sheet (`SkillDrawer.tsx`, live pause = `POST /v1/skills/{id}/state` on the world client), 3-step `TeachWizard.tsx` over `useTeach` (captures, version, save); Try run and examples have no route and stay disabled.
## App (WEB-3a, `app/`)
- `src/Root.tsx` shows the old app, or the lazy `app/ParkApp.tsx` under `/park` (`isParkPath`).
- `AppCtx.ts` is the `app` prop. `store.ts` (framework-free, injected `schedule`) holds decisions, started
  worlds, prefs and the toast. `context.tsx`: `ParkProvider`, `useApp`, `useParkApi` (notes each result's
  `source`), `useSchedule` (the injected timer: pages never call setTimeout). `router.ts` alone reads the address bar.
- `pages.ts`: one line per page, `home: lazy(() => import("../pages/Home/HomePage").then(...)),`; nothing else changes.
- `pages/Home/` (WEB-4; Studio layout UI-STUDIO-2): one column (greeting + still crew, the ask box with the Quick answer /
  Make a world switch, Your worlds cards, Chat history as an honest empty state, side column Needs you / Up next / Just
  finished / spend / tiles); no `<main>`, no h1 but the greeting; no map pins; the Studio theme veils the city behind Home.
## Shell (WEB-3b, `shell/`)
- `AppShell` (named export, `children` only) holds the nav, popovers, one `<main>`, toast, loader, boot (`park.shell.css`: no motion, blur on the nav only); ParkApp owns `[data-park]`. QA-DEMO-1: below 840px the tabs are one page button + `Menu` (`TopNav compact`); UI-STUDIO-INT: from 840px the tabs that do not fit beside the tools (`shell/navFit.ts`, width-only, priority Home, Chat, Worlds, Needs you, Skills, Agenda, Team, Ledger) sit in a More menu that names the current page when it holds it; the sample banner sits in the page column, pinned under the nav on Home.
- The city is STATIC (motion and its honesty-scan entry: BQ-WEB-3): `scene.ts` caches a scene per `time|motion` at module level, with the 3 pin points for `app.pins`.
- `usePageApp()` is what pages get: `go('world')` runs the loader first (`store.openWorld`); `useApp().go` stays immediate. `app/NotFound.tsx` is an unknown route and an unknown world id; `app/buildStamp.ts` is the vite-defined short commit sha (Home footer, `<meta name="tilo-build">`).
- `sample/` (STARTER-1, BQ-STARTER-1): the API's recorded sample project `w_sample_village_basic` (`World.sample`, `sample: true` on the list item): `SampleBadge`/`SampleNote` on the Home card, Worlds row and world page; Hide is `localStorage` (`sampleChoice.ts`, try/catch), "Show sample project" makes `getWorlds` ask `?include_sample=1`; `HttpClient.post` and `sendJson` never sends a write for its path (the message says the answer was not sent; nothing is simulated). QA-DEMO-1: `ParkProvider.demo` (`useDemoSession`: no injected Api, a url, an anonymous session) makes a start say "Demo sessions replay a recorded run" and opens the sample world, and `decide` toast "Sample data: nothing was approved", never a simulated run or approval (HR-1). JUDGE-FIRST-RUN (15 Oct audit): a first visit's Home leads with `FirstTaskCard` (`firstTask.ts`: three real tasks that only fill the task box, plus a button that opens the recorded sample: `showSample()` then `go('world', sample id)`, because the world page only knows ids the list carries); Agenda, Skills and Team keep their real page and add the labelled `FirstRunPanels embedded` below it (Ledger still swaps); `api/coalesce.ts` shares one in-flight `/worlds` and `/cards` read between callers; Home shows `HomeSkeleton` while its first reads are out; the composer's Size of job sits in a native `<details>` Options beside the Quick answer / Make a world switch (open once it is not Quick task); Home spend uses the ledger's own currency (live is USD), never an assumed pound.
- Team worlds (BQ-CTX-TEAMWORLD, ADR-0040, `api/live/teamShares.ts`, `pages/World/TeamShare.tsx`): the owner's Share with team dialog (consent copy, the person's own memberships from `GET /v1/people`, live list, `HttpClient.sendJson` PUT/DELETE; a row says Shared only from the re-read list). `TeamWorld.tsx`: a listed world with `World.access` `team` (the list item's `access: "team"`, TSW-4b) opens read only through `GET /worlds/{id}` (404 = missing world); a live id the list does not carry is the same missing world with no request (`MissingWorld`); team items are list rows (owner's page reads them on a click). TSW-5: `AddWorkItem` (`api/live/workItems.ts`, POST /v1/work-items; personal by default, one Idempotency-Key per attempt, 'Added' only from the answer) sits under the team list. `ShareLine` (`api/live/shareLine.ts`) reads the latest `world.share_changed` per team from `GET /worlds/{id}/events` and shows nothing when none or unreadable.

- WORLD-USEFUL (`pages/World/RunStatus.tsx`, `runView.ts`, `useRunResult.ts`, `markdown.tsx`): a real run's World page opens with one status banner derived from recorded events only (`runView`: "Step n of m: what the agents do now" from `world.planned.unit_count` + unit events; "Assumed: ..." chips from events whose summary says so; `world.failed` data.reason with "Start it again"), and, once `artifact.delivered` + `world.completed` are recorded, the delivered text read from `GET /worlds/{id}/result` and shown readable with Open result / Download; with several delivered items each is listed with Open/Download read from `?artifact=<id>` (RESULT-LIVE). The chip, agent count and bar follow the events (`withRunState`), not the list read at page open; a failed run is "Stopped", never "Ready". `POST /worlds/{id}/rerun` restarts any stopped (`world.failed`) world (RERUN-ANY); only a server refusal (a 409 for a world still running, finished or with nothing approved) says so and offers New task.

## Local rules
- Import nothing from `screens/`, `world/`, `stage/` (only the shared `src/api`, `src/router` seams and the few engine modules named in `park.static.test.ts`). No `window` globals, no model ids, no design runtime port.
- `engines/kit.ts`: `createKit` builds a fresh cache per call; hold one kit per document (a provider), or world and building memoisation is lost. Browser notifications (FR-CHN-17d, BQ-CHN17d-1): `pages/Profile/PushControl.tsx` (live signed-in session only, off by default), `api/push.ts`, worker `public/push-sw.js`.
